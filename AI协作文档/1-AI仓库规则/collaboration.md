# Collaboration — AI 协作规范

> 本文件说明 AI 在本仓库中如何协作。AI 在接收任务后，应先阅读本文了解工作流程和归档规则。

## 协作流程

一次完整的 AI 协作包含以下阶段。详细的分阶段开发流程请参考 `协作资产/skills/分阶段协作开发Skill.md` 和 `协作资产/spec/协作规约Spec.md`。

```
1. 需求提出       → 人类说明背景、目标、范围
2. 需求复述       → AI 复述并确认理解
3. 代码阅读       → AI 阅读相关代码，不凭空设计
4. 分阶段方案     → AI 给出方案和确认问题
5. 人工确认       → 人类答复或协商方案
6. 阶段执行       → AI 执行当前阶段（只改当前阶段内容）
7. 测试验证       → AI 编写或运行测试
8. 阶段汇报       → AI 汇报成果和验证结果
9. 人工检查       → 人类检查阶段成果
10. 修正或继续    → 反馈修正 → 进入下一阶段
11. 归档记录      → 协作结果写入 session / archive
```

### 需求提出规范

人类向 AI 提出需求时，建议包含以下信息：

- **背景**：为什么要做这个
- **目标**：期望达成的效果
- **范围**：涉及哪些端（Web/桌面端/Android/后端）
- **示例**：如果适用，给出输入输出样例
- **优先级**：P0/P1/P2

AI 会根据这些信息复述需求并输出分阶段方案。

## 归档规范

每轮 AI 协作结束后必须归档。归档规则以 `协作资产/archive-schema.md`（位于项目根目录 `2-沉淀产物/`）为准。

### 归档类型

| 类型 | 是否有 | 说明 |
|------|--------|------|
| `session` | 必有 | 记录一次协作过程和阶段性结果 |
| `archive` | 按需 | 长期复用的提炼内容 |
| `spec` | 按需 | 任务定义（目标、范围、验收标准） |
| `skill` | 按需 | AI 角色职责定义 |
| `rules` | 按需 | 多轮验证有效的固定做法 |
| `summary` | 按需 | 阶段性复盘 |

### 文件命名

```
{姓名}-{类型}-v{版本}-{MM-DD}[-{序号}].md
```

示例：
- `zby-session-v1.0-05-23.md`
- `why-archive-v1.0-05-25.md`

### 归档路径

所有归档文件统一放在 `协作资产/` 下（对应项目根目录 `2-沉淀产物/`）：

```
协作资产/
  sessions/        # 会话记录
  archive/         # 长期归档
  spec/            # 规范定义
  skills/          # AI 技能
  rules/           # 固定规则
  summaries/       # 阶段总结
```

---

## 写入规则

1. **只写入实际存在的内容**。不要写入还没实现的理想架构。
2. **不覆盖已有文件**。同名文件补后缀（如 `-2`），不得删除旧文件。
3. **使用模板**。归档前参考对应目录下的 `*-template.md`。
4. **重点在提炼，不在转存**。不要复制聊天原文，提取关键决策和结果。

## 需要人工确认的操作

以下操作 AI 不能独立完成，必须由人类成员确认：

- 修改数据库 schema 或创建迁移
- 修改 `requirements.txt` 或 `package.json` 依赖
- 修改 `.env` 或密钥相关配置
- 合并分支或推送代码
- 部署到生产环境
- 删除文件或目录
- 将 session 升级为 spec / skill / rules

## 禁止的行为

- 修改 `.claude/settings.local.json` 中的权限配置
- 删除 `.planning/` 下的规划文档
- 覆盖已有的 session / archive 文件
- 在未确认的情况下合并冲突代码
- 提交未经过人工审核的代码

## 自我迭代

> 版本：v1.0 | 最后更新：2026-06-08 | 更新人：zby

### 修改流程

1. 团队协作方式变化时，更新本文件
2. 在文件头部更新版本号和日期
3. 修改需至少两人 review 确认（协作规范影响全团队）
4. 重要变更应在 `summaries/` 中记录

### 触发条件

- 归档流程发生变化
- 需要人工确认的操作范围调整
- 团队成员分工变化
- 发现 AI 频繁违反某条规则（说明规则需要优化）
