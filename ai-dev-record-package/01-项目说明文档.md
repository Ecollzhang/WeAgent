# 项目说明文档

## 项目定位

WeAgent 是一个以 IM 聊天为核心交互方式的多 Agent 协作平台原型。项目目标不是只做一个普通聊天界面，而是让用户通过会话、Agent 角色、工具能力、沙箱运行时和产物展示，与 Claude Code、Codex、OpenCode 或自定义 Agent 协作完成代码、网页、文档、PPT 等产物。

本交付包的重点是展示开发过程中的 AI 协作痕迹，包括需求讨论、阶段规划、Spec、Skill、Rules、Session、Archive、Summary、UAT、验证记录和分支演进。

## 为什么整理这个包

比赛或项目评审通常不只看最终代码，还会看 AI 是否真正参与了开发流程。本包把分散在分支、规划目录和协作归档中的材料聚合起来，形成可追溯证据：

- 需求如何被拆解成阶段和验收标准。
- AI 如何参与方案设计、计划生成、风险识别和验证。
- 人类成员如何通过分支、提交、UAT 和归档把 AI 输出沉淀为项目资产。
- Spec、Skill、Rules 等 AI 协作资产如何进入项目文档体系。

## 交付包结构

`sources/branches/` 保存三个分支抽取出的文档与规划记录：

- `agent_adapter/`：Agent Adapter、消息流规范、上下文系统相关记录。
- `feature_toolset/`：Toolset capability、Skill/MCP/Plugin/Tool、导入、安全审查、UAT 与 checkpoint 记录。
- `combine_toolset_v1.1.0/`：桌面端融合、多 provider runtime、沙箱服务代理、Phase 03/04 验证记录。

`sources/original-references/` 保存原始参考材料：

- `AgentHub 多 Agent 协作平台深度研究报告.pdf`
- `AgentHub 多 Agent 协作平台研究报告草案.pdf`
- `AgentHub- 多Agent协作平台设计-feishu.pdf`
- `agenthub_tech_solution_markdown_draft.md`

`sources/current-worktree/planning-tmp-evidence/` 保存有效运行证据，包括 UI 截图、开发日志和 UAT JSON。该目录另有 `README.md` 说明每组截图和日志对应的验证意义。

## 核心交付视角

本包使用“协作证据链”组织材料：

1. 原始命题和研究材料提供项目背景。
2. `docs/ai-collab` 定义如何记录 AI 协作。
3. `.planning` 将需求、阶段、计划和验证持续沉淀。
4. 分支提交记录展示功能演进路径。
5. UAT、截图、日志和测试结果证明协作结果经过验证。

因此，本包适合作为答辩、复盘、项目归档和 AI 协作能力展示材料。
