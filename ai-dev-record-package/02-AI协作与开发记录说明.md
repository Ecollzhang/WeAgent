# AI 协作与开发记录说明

## 协作记录来源

本项目的 AI 协作痕迹主要来自四类材料：

- `docs/ai-collab/`：专门用于记录 AI 对话归档、session、summary、spec、skill、rules 的目录。
- `.planning/`：GSD 式开发规划目录，记录项目上下文、需求、路线图、阶段计划和验证。
- `docs/report/`：阶段性调试、合并、运行时设计和验证报告。
- `.planning/tmp` 有效证据：运行截图、日志和 UAT JSON。

这些材料共同说明：AI 不只是生成代码片段，而是参与了需求分解、方案比较、风险识别、任务规划、验收设计和问题修复。

## `docs/ai-collab` 的作用

`docs/ai-collab/archive-schema.md` 明确说明，本项目需要把 AI 聊天从零散对话沉淀为可复用资产。它把记录分为：

- `session`：单轮协作过程，默认必有。
- `archive`：对已结束对话中长期有价值内容的提炼。
- `summary`：阶段复盘和方法总结。
- `spec`：任务目标、范围、输入输出和验收标准。
- `skill`：AI 角色职责、输入输出和边界。
- `rules`：多轮验证后稳定下来的固定做法。

这套结构直接服务于“AI 协作能力可展示、可追溯”的目标。

## `.planning` 的作用

`.planning` 是开发过程的主线记录。它保存：

- `PROJECT.md`：项目当前上下文和工作约束。
- `REQUIREMENTS.md`：阶段需求和编号要求。
- `ROADMAP.md`：阶段路线图。
- `STATE.md`：当前状态、决策和最新验证。
- `phases/`：每个阶段的上下文、计划、SPEC、VERIFY、checkpoint 和 handoff。

这些文件展示了开发不是一次性完成，而是经过多轮计划、执行、验证和修正。

## 有代表性的 AI 协作证据

`origin/agent_adapter` 中的记录显示，项目先建立 Agent Adapter 和消息流接入规范，解决 Claude Code 与 Codex 输出差异、统一事件协议、fallback 和前端流式展示问题。

`origin/feature/toolset` 中的记录显示，项目进一步把 Skill、Tool、MCP、Plugin 抽象为同级 capability，并围绕版本、权限、导入、安全审查、运行时投影和 UAT 建立完整机制。

`origin/combine/toolset_v1.1.0` 中的记录显示，项目把 toolset 与桌面端、多 provider sandbox runtime、service proxy 和桌面 Toolset Adapter 融合，并留下明确的测试与验证结果。

## 人类与 AI 的分工关系

从记录看，人类成员承担目标设定、边界确认、分支选择、验收判断和最终取舍；AI 承担方案扩展、计划拆解、实现路径建议、验证清单生成、调试记录整理和文档沉淀。

这是一种“人类给方向和判断，AI 承担推理、执行建议和记录整理”的协作模式。
