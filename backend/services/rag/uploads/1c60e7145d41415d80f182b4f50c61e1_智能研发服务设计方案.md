# WeAgent 智能研发（Smart R&D）领域服务设计方案

## 一、概述

基于 WeAgent 已有的 Agent 调度引擎、Docker 沙箱、多引擎适配、RAG 知识库等基础设施，为智能研发领域构建专属的协作空间。目标是让开发者拥有一个"AI 全栈团队"——从项目初始化、代码生成、代码审查到测试生成和文档输出，全流程 AI 协作。

### 现有基础

| 能力 | 说明 |
|------|------|
| RD Agent 类别 | 5 类（文档/编程/测试/设计/数据分析），约 12 个预定义 Agent |
| 内置工具 | 24 个（代码执行、文件操作、Git、代码审查、RAG 搜索等） |
| 调度引擎 | 主持 Agent + Worker Agent 双层调度 |
| 执行环境 | Docker 沙箱隔离 |
| 领域网关 | `/api/domain/rd/*` → `127.0.0.1:5101/api/rd/*` |
| 前端占位 | 4 个占位路由（/projects, /repos, /reviews, /builds） |

## 二、功能规划

### 功能一：研发项目工作台（Phase 1，已完成后端，前端待联调）

项目管理中枢，开发者创建项目并设定技术栈后，所有对话变为"项目感知"——Agent 自动了解项目背景、技术栈和已有代码文件。

**具体功能**：

- **创建项目**：填写名称、描述，选择技术栈（前端框架/后端框架/数据库/部署方式）
- **项目仪表盘**：技术栈概览卡片、代码产物数、文件树
- **项目感知对话**：在项目下创建会话时，Agent 系统提示词自动注入项目上下文（技术栈、文件结构）
- **代码产物管理**：Agent 生成的代码文件自动归入项目文件树，支持浏览和删除
- **技术栈模板**：前端内置 4 类选项，覆盖主流框架（Vue/React/Angular、Flask/Django/Spring Boot、MySQL/PostgreSQL/MongoDB 等）

**为什么实用**：真实开发中，每次跟 AI 对话都要重复"我在用 Vue 2 + Flask + Element UI..."。项目上下文自动注入后，Agent 无需反复告知技术背景。

---

### 功能二：智能代码审查（Phase 2，待开发）

提交代码 → 多 Agent 并行审查 → 结构化审查报告。

**审查流程**：

```
用户提交代码（粘贴/上传/从项目选择）
  → 主持 Agent 制定审查计划（安全/规范/逻辑/性能四个维度）
  → Worker Agent 并行审查：
    ├─ 安全审查 Agent：OWASP Top 10、注入漏洞、认证缺陷
    ├─ 规范审查 Agent：命名规范、代码风格、最佳实践
    ├─ 逻辑审查 Agent：边界条件、错误处理、潜在 Bug
    └─ 性能审查 Agent：N+1 查询、内存泄漏、算法复杂度
  → 主持 Agent 汇总 → 结构化审查报告
```

**报告内容**：总评分（1-10 分，分维度打分）、问题列表（严重/警告/建议三级，含代码位置和修复建议）、安全风险清单。

**为什么实用**：Code Review 是研发最高频场景之一。多 Agent 并行审查比单 AI 更全面（不同 Agent 关注不同维度），结构化报告比 Chat 文本回复更专业可用。

---

### 功能三：技术方案一键生成（Phase 3，待开发）

输入需求描述 → Agent 团队输出完整技术方案文档。

**输出内容**：系统架构设计、API 接口设计（RESTful 端点列表+请求/响应格式）、数据库设计（ER 描述+DDL）、前端组件树+路由设计、技术选型说明+实施步骤。

---

### 功能四：智能测试生成（Phase 3/4，待开发）

提供源代码 → Agent 自动生成单元测试和集成测试（覆盖核心逻辑、边界条件、异常路径），可在沙箱中直接运行验证。

---

### 功能五：依赖安全扫描（Phase 4，待开发）

上传 `requirements.txt` 或 `package.json` → 解析依赖 → 查询公开漏洞库 → 输出安全报告（CVE 编号、严重等级、影响版本、修复建议）。

### 3.2 代理转发机制

前端请求 `/api/domain/rd/projects` → 主后端 `domain_proxy_controller.py` 匹配路由 `/api/domain/<domain>/<path:subpath>` → 转发到 `http://127.0.0.1:5101/api/rd/projects` → RD 服务处理并返回。

```
前端 axios baseURL="/api"
  → GET /api/domain/rd/projects
  → 主后端转发到 http://127.0.0.1:5101/api/rd/projects
  → RD 服务 blueprint route /api/rd/projects
```

### 3.3 核心技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 项目上下文注入 | 非侵入式（方案 B） | 前端携带上下文，不修改核心 Agent 调度引擎，降低耦合 |
| 代码审查调度 | 复用现有对话系统 | 主持 Agent → delegate_task() → Worker Agent，完全复用 |
| 代码高亮展示 | highlight.js | 轻量够用，比赛阶段不需要 Monaco Editor 的完整 IDE 能力 |
| 外部仓库集成 | 比赛阶段不做 | 聚焦文件粘贴和上传，降低外部 API 依赖风险 |
| 代码产物存储 | 项目维度索引 | rd_project_files 作为文件索引，与 Artifact 系统互补不冲突 |

## 四、数据库设计

```sql
-- 研发项目表
CREATE TABLE rd_projects (
    id VARCHAR(36) PRIMARY KEY,
    workspace_id VARCHAR(36) NOT NULL,
    user_id VARCHAR(36) NOT NULL,
    name VARCHAR(200) NOT NULL COMMENT '项目名称',
    description TEXT COMMENT '项目描述',
    tech_stack JSON NOT NULL COMMENT '{"frontend":"Vue","backend":"Flask","database":"MySQL","deployment":"Docker"}',
    status ENUM('active','archived') DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_workspace (workspace_id),
    INDEX idx_user (user_id)
);

-- 项目文件表（Agent 生成的代码产物）
CREATE TABLE rd_project_files (
    id VARCHAR(36) PRIMARY KEY,
    project_id VARCHAR(36) NOT NULL,
    conversation_id VARCHAR(36) COMMENT '来源会话ID',
    file_name VARCHAR(500) NOT NULL,
    file_path VARCHAR(1000) NOT NULL,
    content LONGTEXT COMMENT '文件内容',
    file_type VARCHAR(50) COMMENT 'py/js/vue/sql等',
    size INT DEFAULT 0,
    version INT DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES rd_projects(id) ON DELETE CASCADE,
    INDEX idx_project (project_id)
);

-- 代码审查记录表（Phase 2）
CREATE TABLE rd_reviews (
    id VARCHAR(36) PRIMARY KEY,
    project_id VARCHAR(36),
    conversation_id VARCHAR(36),
    user_id VARCHAR(36) NOT NULL,
    title VARCHAR(300) NOT NULL,
    code_content LONGTEXT NOT NULL,
    language VARCHAR(50),
    status ENUM('pending','reviewing','completed','error') DEFAULT 'pending',
    summary TEXT COMMENT '审查总结',
    score DECIMAL(3,1) COMMENT '总评分 1-10',
    scores JSON COMMENT '{"security":8.5,"style":7.0,"logic":9.0,"performance":6.5}',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_project (project_id),
    INDEX idx_user (user_id)
);

-- 审查问题明细表（Phase 2）
CREATE TABLE rd_review_issues (
    id INT AUTO_INCREMENT PRIMARY KEY,
    review_id VARCHAR(36) NOT NULL,
    severity ENUM('critical','warning','info') NOT NULL,
    category VARCHAR(50) NOT NULL COMMENT 'security/style/logic/performance',
    file_name VARCHAR(500),
    line_number INT,
    title VARCHAR(300) NOT NULL,
    description TEXT,
    suggestion TEXT COMMENT '修复建议',
    code_snippet TEXT COMMENT '问题代码片段',
    FOREIGN KEY (review_id) REFERENCES rd_reviews(id) ON DELETE CASCADE,
    INDEX idx_review (review_id)
);

-- 技术方案表（Phase 3）
CREATE TABLE rd_tech_specs (
    id VARCHAR(36) PRIMARY KEY,
    project_id VARCHAR(36) NOT NULL,
    conversation_id VARCHAR(36),
    user_id VARCHAR(36) NOT NULL,
    title VARCHAR(300) NOT NULL,
    requirements TEXT COMMENT '原始需求描述',
    content JSON COMMENT '{"architecture":"...","api":"...","database":"...","frontend":"...","plan":"..."}',
    status ENUM('draft','completed') DEFAULT 'draft',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES rd_projects(id) ON DELETE CASCADE,
    INDEX idx_project (project_id)
);
```


### 6.3 关键修复记录

**问题 1：`app.py` 与核心 `app/` 包命名冲突**

`setup.py` 通过 `find_packages(include=['app', 'app.*'])` 将核心包命名为 `app`，而 RD 服务的 `app.py` 在 `sys.path` 中会遮蔽核心包。

**解决方案**：
- `app.py` → `main.py`（避免模块名冲突）
- `from app import db` → `from main import db`（models 和 services 中 3 个文件同步更新）
- `sys.path.insert(0, ...)` → `sys.path.append(...)`（确保本地模块优先于 `backend/` 中的同名模块）

**问题 2：`load_dotenv()` 找不到 `.env` 文件**

原因：未指定 `.env` 文件路径，Python 从 CWD 查找。

**解决方案**：显式传入绝对路径
```python
_RD_DIR = os.path.abspath(os.path.dirname(__file__))
load_dotenv(os.path.join(_RD_DIR, '.env'))
```

| 2.2 审查 API | `review_controller.py`（POST 创建审查 / GET 列表 / GET 详情） |
| 2.3 审查业务逻辑 | `review_service.py`：创建审查记录 → 通过 conversation 触发多 Agent 审查 → 监听结果回写 |
| 2.4 多 Agent 审查工作流 | 在 RD 服务中创建"审查会话"，主持 Agent 制定审查计划（4 个维度），通过 `delegate_task()` 分派给 Worker Agent 并行执行 |
| 2.5 审查报告生成 | 汇总 4 个 Worker Agent 的输出，解析为结构化 JSON（评分+问题列表），写入 `rd_reviews` 和 `rd_review_issues` |
| 2.6 前端审查列表页 | `RdReviews.vue` — 审查历史卡片列表（评分+状态+时间） |
| 2.7 前端审查详情页 | `RdReviewDetail.vue` — 总评分仪表盘 + 4 维度分别展示 + 问题卡片列表（严重级别颜色标签 + 代码片段 + 修复建议） |
| 2.8 代码提交弹窗 | `SubmitCodeDialog.vue` — 粘贴代码 textarea + 语言选择 + 标题输入 |
| 2.9 路由注册 | `/reviews` → RdReviews, `/reviews/:id` → RdReviewDetail |

**验收标准**：
- 提交一段代码 → 系统自动创建审查会话 → 4 个 Agent 并行审查 → 返回结构化报告
- 报告包含 4 个维度的评分（security/style/logic/performance）和问题列表
- 每个问题标注严重级别（critical/warning/info）、代码位置、修复建议

## 十、启动方式

```bash
# 1. 创建数据库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS weagent_rd DEFAULT CHARSET utf8mb4;"

# 2. 配置环境变量（可选，有默认值）
cd backend/services/rd
cp .env.example .env   # 如需自定义 MYSQL_PASSWORD 等

# 3. 启动 RD 服务
python main.py
# → [WeAgent] 智能研发服务启动 → http://127.0.0.1:5101

# 4. 前端开发服务器（如未启动）
cd frontend
npm run serve
# → 前端通过 http://localhost:8080 访问
# → RD API 经主后端网关代理: /api/domain/rd/* → :5101
```
