```
│  ┌──────────┐  ┌──────────┐  ┌────────────────────┐        │

└─────────────────────────────────────────────────────────────┘
         │                  │                  │
         ▼                  ▼                  ▼
    ┌────────┐        ┌────────┐        ┌────────┐
    │ 成员A  │        │ 成员B  │        │ 成员C  │
    │ 智能研发│        │ 智慧教育│        │ 智慧办公│
    └────────┘        └────────┘        └────────┘

队友拿到地基后，各自只需做：
  1. 在自己的 services/{domain}/ 下写 Controller、Service、Model
  2. 在自己的 weagent_{domain} 库中建表
  3. 在自己的 grayscale_config 种子数据中添加领域配置项
  4. 写自己的前端页面（views/{domain}/）
  5. 在前端侧边栏插槽中添加自己的菜单项
```

**队友不需要关心**：
- JWT 鉴权怎么实现（基座已处理）
- 请求怎么从核心服务转发到领域服务（网关已配置）
- 灰度开关怎么生效（Store + 全局方法已提供）
- 数据库怎么连（config.py + .env 模板已给）
- Flask 错误处理、健康检查（基座已处理）

## 2. 地基要交付什么

| 交付物 | 队友怎么用 | 验收标准 |
|---|---|---|
| **weagent_core 包** | `from weagent_core.services.domain_base import DomainServiceBase` | `pip install -e .` 后能 import |
| **workspaces 表 + CRUD API** | 前端调用创建/切换工作空间 | `POST /api/workspaces` 创建，`GET /api/workspaces` 列表 |
| **grayscale_config 表 + CRUD API** | 前端拉取领域灰度配置 | `GET /api/grayscale/config?domain=edu` 返回配置列表 |
| **领域代理网关** | `/api/domain/edu/courses` 自动转发到 `:5102` | curl 核心服务能透传到领域服务 |
| **rd/edu/office 服务骨架** | 队友在骨架基础上加自己的路由 | 三个服务都能启动，`/health` 返回 200 |
| **前端 WorkspaceSwitcher** | 用户切换工作空间 | 切换后侧边栏菜单变化，灰度配置重新加载 |
| **前端 Grayscale Store** | 队友在组件中用 `isUIVisible('key')` | 灰度开关能控制组件显隐 |
| **前端侧边栏重构** | 队友在领域区域添加自己的菜单项 | 切换领域时菜单正确切换 |
| **前端灰度控制台** | 管理员开关各领域的功能 | 控制台可查看/修改灰度配置 |
| **前端路由框架** | 队友添加自己的领域路由 | 领域路由有 domain meta 标记 |

```sql
CREATE TABLE IF NOT EXISTS workspaces (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(36) NOT NULL,
    domain VARCHAR(50) NOT NULL COMMENT 'rd / edu / office',
    name VARCHAR(200) NOT NULL,
    description TEXT,
    icon VARCHAR(50) DEFAULT 'default',
    sort_order INT DEFAULT 0,
    status ENUM('active', 'archived') DEFAULT 'active',

    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    UNIQUE KEY uk_user_domain_name (user_id, domain, name)
```

**1.5 已有数据迁移（重要）**

系统已有用户、会话、Agent等数据，这些都属于研发领域。需要编写迁移脚本：

```sql
-- backend/sql/migration_v2_data.sql （数据迁移，DDL之后执行）

-- 第一步：为每个已有用户创建默认的"我的研发空间"
INSERT INTO workspaces (id, user_id, domain, name, description, icon, status)
SELECT
    UUID() as id,
    u.id as user_id,
    'rd' as domain,
    '我的研发空间' as name,
    '系统自动创建的默认研发工作空间，包含您已有的所有会话' as description,
    'default' as icon,
    'active' as status
FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM workspaces w
    WHERE w.user_id = u.id AND w.domain = 'rd' AND w.name = '我的研发空间'
);

-- 第二步：将已有会话关联到对应用户的研发空间
UPDATE conversations c
SET workspace_id = (
    SELECT w.id FROM workspaces w
    WHERE w.user_id = c.user_id AND w.domain = 'rd'
    LIMIT 1
)
WHERE c.workspace_id IS NULL;
```

这个迁移脚本确保了：
- 老用户登录后，已有的所有会话自动归属到"我的研发空间"
- WorkspaceSwitcher 中能看到这个空间
- 不需要用户手动迁移任何数据

```python
# backend/app/services/domain_base.py
"""
领域服务基座。
安装 weagent-core 后：from weagent_core.services.domain_base import DomainServiceBase
"""
import os
from flask import Flask, jsonify
from flask_sqlalchemy import SQLAlchemy
from flask_jwt_extended import JWTManager
import redis


class DomainServiceBase:
    def __init__(self, config):
        self.config = config
        self.service_name = config.SERVICE_NAME
        self.port = config.PORT

        self.app = Flask(self.service_name)
        self.app.config.from_object(config)

        self.db = SQLAlchemy(self.app)
        self.jwt = JWTManager(self.app)

        redis_url = getattr(config, 'REDIS_URL', 'redis://127.0.0.1:6379/0')
        self.redis = redis.Redis.from_url(redis_url, decode_responses=True)

        self._register_error_handlers()
        self._register_health_check()

    def _register_error_handlers(self):
        @self.app.errorhandler(404)
        def not_found(e):
            return jsonify({
                'code': 404, 'error': 'Not found', 'service': self.service_name
            }), 404

        @self.app.errorhandler(500)
        def server_error(e):
            return jsonify({
                'code': 500, 'error': 'Internal error', 'service': self.service_name
            }), 500

    def _register_health_check(self):
        @self.app.route('/health')
        def health():
            return jsonify({
                'service': self.service_name,
                'status': 'ok',
                'port': self.port
            })

    def run(self):
        self.app.run(host='127.0.0.1', port=self.port, debug=False)
```

**3.1 Workspace API**

```
POST   /api/workspaces              # 创建工作空间

GET    /api/workspaces/{id}         # 获取单个工作空间详情
```

```python
# backend/app/controllers/workspace_controller.py
from flask import Blueprint, request, jsonify
from flask_jwt_extended import jwt_required, get_jwt_identity
from app.services.workspace_service import WorkspaceService

workspace_bp = Blueprint('workspace', __name__)

@workspace_bp.route('/api/workspaces', methods=['POST'])
@jwt_required()
```

**3.3 领域代理网关**

```python
# backend/app/controllers/domain_proxy_controller.py
import os
import requests
from flask import Blueprint, request, jsonify
from flask_jwt_extended import jwt_required, get_jwt_identity

domain_proxy_bp = Blueprint('domain_proxy', __name__)

DOMAIN_SERVICE_MAP = {
    'rd': os.getenv('RD_SERVICE_URL', 'http://127.0.0.1:5101'),
    'edu': os.getenv('EDU_SERVICE_URL', 'http://127.0.0.1:5102'),
    'office': os.getenv('OFFICE_SERVICE_URL', 'http://127.0.0.1:5103'),
}
PROXY_TIMEOUT = int(os.getenv('PROXY_TIMEOUT', 30))

@domain_proxy_bp.route('/api/domain/<domain>/<path:subpath>',
                       methods=['GET', 'POST', 'PUT', 'DELETE'])
@jwt_required()
def proxy_to_domain(domain, subpath):
    """
    将 /api/domain/rd/xxx   转发到 :5101/api/rd/xxx
    将 /api/domain/edu/xxx  转发到 :5102/api/edu/xxx
    将 /api/domain/office/xxx 转发到 :5103/api/office/xxx

    Agent相关的API（/api/agents, /api/messages等）仍然直接由核心服务处理，
    不经过此网关。此网关只转发领域特有的业务API。
    """
    if domain not in DOMAIN_SERVICE_MAP:
        return jsonify({'code': 404, 'error': f'Unknown domain: {domain}'}), 404

    target_url = f"{DOMAIN_SERVICE_MAP[domain]}/api/{domain}/{subpath}"

    headers = {k: v for k, v in request.headers.items()
               if k.lower() not in ('host', 'content-length')}
    headers['X-Forwarded-User'] = get_jwt_identity()

    try:
        resp = requests.request(
            method=request.method,
            url=target_url,
            headers=headers,
            json=request.get_json(silent=True),
            params=request.args,
            timeout=PROXY_TIMEOUT
        )
        return jsonify(resp.json()), resp.status_code
    except requests.exceptions.ConnectionError:
        return jsonify({
            'code': 502,
            'error': f'Domain service {domain} is not available',
            'service': 'gateway'
        }), 502
    except requests.exceptions.Timeout:
        return jsonify({
            'code': 504,
            'error': f'Domain service {domain} timeout',
            'service': 'gateway'
        }), 504
```

## 5. 决策确认（已确认）

| 问题 | 决策 | 说明 |
|---|---|---|
| Q1 数据库迁移 | ✅ **A** 独立 `migration_v2.sql` | 手动执行，不影响现有 init.sql |
| Q2 代理路径前缀 | ✅ **加特殊前缀** `/api/domain/{domain}/xxx` | 避免与核心 `/api/agents` 等路由冲突。Agent相关请求全部走核心服务，领域服务只负责该领域的数据处理和存储 |
| Q3 前端灰度 mixin | ✅ **全局 mixin** | `Vue.mixin(grayscaleMixin)`，所有组件可直接使用 `isUIVisible()` / `isFeatureEnabled()` |
| Q4 新用户默认空间 | ✅ **A 空状态引导创建** | 首次登录显示引导页，用户手动创建第一个工作空间 |
| Q5 灰度控制台权限 | ✅ **仅管理员** | `role === 'admin'` 才显示入口和允许访问 |
| Q6 领域服务运行方式 | ✅ **A 宿主机直接运行** | 开发阶段 Python 进程运行，比赛时再考虑 Docker |
| Q7 JWT Secret | ✅ **A 核心服务 .env 统一管理** | 领域服务 `.env.example` 中标注 `JWT_SECRET_KEY=请从核心服务.env中复制` |
| Q8 RAG 骨架 | ✅ **B 一起创建** | RAG 服务骨架和三个领域骨架一起交付 |
