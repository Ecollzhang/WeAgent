# 原命题拆解与 MVP 范围

本文档将原命题拆成可交付的技术范围。目标不是实现一个完整商用平台，而是在 12 天内做出一个能证明方向成立、能演示、能答辩的 AgentHub MVP。

## 1. 原命题一句话

AgentHub 是一个以 IM 聊天为核心交互的多 Agent 协作平台。用户像使用飞书或微信一样新建对话、选择 Agent、发送消息、在群聊中 @ 多个 Agent，由 Orchestrator 协调多个 Agent 完成网页、Workflow、代码、文档等产物。

## 2. 评审关注点拆解

| 评审维度 | 权重 | 技术方案响应 |
|---|---:|---|
| AI 协作能力 | 30% | 沉淀 Spec、skill、rules、AI 协作记录，并展示如何让 AI 参与开发 |
| 功能完整度 | 25% | 跑通 IM 核心体验、单聊、群聊、多 Agent 调度 |
| 生成效果质量 | 20% | 聊天 UI、流式消息、产物卡片、网页预览、代码查看 |
| 代码理解度 | 15% | 架构分层清楚，接口、事件协议和模块边界可解释 |
| 创新与产品感 | 10% | 联系人式 Agent、自建 Agent、产物内联、Demo 剧本化体验 |

## 3. P0 范围

P0 是必须完成的主链路。

| 能力 | P0 目标 |
|---|---|
| IM 会话 | 会话列表、新建会话、最近活跃排序、聊天主界面 |
| 单聊 | 用户选择一个 Agent 后进行多轮对话 |
| 群聊 | 用户在同一会话中 @ 多个 Agent |
| Orchestrator | 根据 @ 或任务意图生成执行计划，调度子 Agent，汇总结果 |
| Agent 接入 | Codex Adapter、Claude Code Adapter、Mock Adapter |
| 流式输出 | 中台将 Agent 输出归一化为 AgentEvent，再通过 SSE 推送前端 |
| 产物卡片 | 代码卡片、网页预览卡片、文件卡片 |
| 自建 Agent | 名称、描述、System Prompt、能力标签、工具权限 |
| 上下文 | 会话历史作为 Agent 输入，支持关键消息 pin 的设计预留 |
| 文档交付 | 技术方案、产品说明、AI 协作记录、Demo 脚本 |

## 4. P1 范围

P1 是优先增强项，时间允许时实现。

| 能力 | P1 目标 |
|---|---|
| 部署状态卡片 | 展示“部署中、成功、失败、预览 URL”等状态，可先模拟 |
| ZIP 导出 | 将 workspace 或 artifact 打包下载 |
| WebSocket | 支持取消任务、审批确认等双向控制 |
| Diff 展示 | 展示代码差异，支持复制或查看 |
| Agent 运行面板 | 展示每个 Agent 的运行状态、耗时、错误 |
| Demo 固定路径 | 一键进入预设演示会话 |

## 5. P2 范围

P2 只做方案预留，不作为 12 天交付承诺。

- 桌面端。
- 移动端。
- 企业级权限后台。
- 完整版本历史。
- 复杂代码冲突合并。
- 真实生产级容器部署。
- PPT、Word、Excel 深度编辑。
- 大规模并发调度。

## 6. MVP 主链路

```text
用户创建会话
 -> 选择单个 Agent 或 @ 多个 Agent
 -> 前端 POST 消息到后端
 -> 后端创建 message 和 run
 -> 中台 Orchestrator 读取 run
 -> 中台调度 Codex / Claude Code / Mock Adapter
 -> Adapter 返回 raw stream
 -> Event Normalizer 转成 AgentEvent
 -> 中台通过 SSE 推送给前端
 -> 后端持久化消息、事件、产物
 -> 前端展示消息气泡和产物卡片
```

## 7. 不做什么

为了保证 12 天交付，本期不把 AgentHub 做成完整长期平台。以下能力如果出现，只作为演示增强，不作为核心技术承诺：

- 不承诺真实多租户。
- 不承诺生产级权限体系。
- 不承诺真实线上部署全链路。
- 不承诺所有 Agent 平台都完整接入。
- 不承诺复杂文件合并和版本管理。
