# Plan 02-01: Conversation Context System

## Goal

Make WeAgent conversations contextful across turns. In the same conversation, Claude/Codex should receive relevant prior transcript and recorded file/artifact context instead of seeing only the newest user message.

## Must Haves

- Turn 2 adapter prompt includes turn 1 user and agent content from the same conversation.
- Turn 2 adapter prompt includes recorded file/artifact context when prior adapter events expose paths.
- Context is scoped to `conversation_id`.
- Provider adapters do not query the database directly.
- `adapter.stream(AgentRequest)` remains the public adapter interface.
- The phase does not claim full Claude/Codex native runtime parity.

## Non Goals

- Native Claude/Codex session resume.
- Interactive choice continuation.
- Full MCP/hook/plan-mode UI.
- Background sub-agent lifecycle tracking.
- Replaying full file contents every turn.

Manual acceptance:

1. Start frontend and backend.
2. Create a conversation with Mock, Claude, or Codex.
3. Send a first message that causes the agent to mention or create a file/artifact.
4. Send a second message: `继续基于刚才的文件/内容说一下下一步。`
5. Confirm the adapter request contains prior context and the agent can refer to the previous turn.

## Risks

- Claude/Codex raw events may not expose every file read path in CLI mode.
- Context prompt can grow too large if transcript and file summaries are not bounded.
- This phase improves WeAgent conversation continuity but still does not provide full native runtime state.
