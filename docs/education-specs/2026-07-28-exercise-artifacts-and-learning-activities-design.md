# Education 习题产物与学习活动设计

日期：2026-07-28  
状态：已确认，待实现  
范围：高中英语、小学语文的阅读与写作场景

## 1. 目标

本轮解决四个直接影响教师验收的问题：

1. 教案字段标题与“放大编辑”操作不能重合。
2. 放大编辑界面应沿用可视化课件编辑器的画布和操作层级，同时保持教案字段的结构化文本语义。
3. 习题生成器必须产生可以校验、预览和发布的真实题目，不得只返回 JavaScript 文件或沙箱路径。
4. “学习活动”需要支持教师创建、附加材料并随课时发布给学生。

本轮不实现 DOCX/PDF 习题导出、自定义 Agent 团队编排、完整题库管理和自动评分。这些能力建立在本轮结构化习题契约之上。

## 2. 核心决策

### 2.1 结构化数据是习题的唯一源产物

习题 Agent 的正式产物是 JSON，不是 `.js`、DOCX 或 PDF。

原因：

- JSON 可以直接校验、编辑、预览和生成学生端安全视图。
- 答案与解析能够和学生可见题面明确分离。
- 后续可以从同一份 JSON 派生 HTML、DOCX、PDF 或 PPTX，避免多份源文件漂移。
- 学情分析可以稳定消费题型、知识点、难度和分值字段。

文档格式属于导出层，而不是 Agent 的主数据格式。

### 2.2 学习活动是发布单元，作业是提交单元

学习活动用于告诉学生“做什么、使用什么材料、预计多久”。活动可以包含阅读、展示、练习、写作和资源查看。

需要学生提交答案、形成版本和接受反馈的内容进入作业模块。普通活动不重复实现提交系统。

### 2.3 教案字段保持结构化纯文本

教学目标、教学活动和评价与作业继续保存为结构化纯文本，不在字段中混入富文本 HTML。

放大编辑器复用课件编辑器的视觉外壳，但只提供适合结构化文本的操作：撤销、重做、编号、项目符号、缩进、减少缩进、清除格式、阅读字号和字数统计。完整字体、颜色、表格和媒体排版仍属于“课件与材料”编辑器。

## 3. 习题 Agent 契约

### 3.1 Agent Skill

习题生成器使用“中英阅读与写作习题设计”Skill，固定执行：

1. 读取课程设计师的教案产物。
2. 提取教学目标、课型、文本类型、学段和时长。
3. 规划题型、目标覆盖、难度梯度、预计用时和分值。
4. 编写题目、标准答案、解析及易错提示。
5. 检查每道题是否可作答、答案是否完整、学生视图是否泄露答案。
6. 写入约定的 JSON 文件并完成 JSON 语法自检。

高中英语重点覆盖阅读证据、语言运用和写作迁移；小学语文根据课文类型覆盖内容理解、语言积累、表达方法和习作迁移。

### 3.2 工具调用

习题生成器只需要以下能力：

1. 沙箱文件读取：读取 `/workspace/shared/lesson_plan_draft.json`。
2. 沙箱文件写入：只写 `/workspace/shared/exercises_draft.json`。
3. JSON 语法检查：写入后执行标准 JSON 解析检查。
4. 课程 RAG：仅当命题依赖课程材料或原文时调用；普通命题不默认联网。

Education 服务在 Agent 完成后调用服务端产物校验器。校验失败时，把文件路径、字段位置和错误原因退回原 Agent 修复一次。第二次仍失败时保留可见文本并标记失败，不把路径回执伪装成习题。

禁止事项：

- 不得生成 `.js`、可执行脚本或动态表达式。
- 不得只回复“文件已生成”或文件路径。
- 不得把答案混入学生可见字段。
- 不得把 `/workspace/shared` 作为跨用户分享机制。

### 3.3 JSON Schema

最小合法产物：

```json
{
  "meta": {
    "title": "课后练习",
    "subject_code": "high_school_english",
    "grade_band": "high_school",
    "estimated_minutes": 15,
    "total_score": 20
  },
  "questions": [
    {
      "id": "Q1",
      "type": "short_answer",
      "prompt": "题目正文",
      "options": [],
      "answer": "参考答案",
      "explanation": "解析",
      "common_mistakes": "易错提示",
      "difficulty": "基础",
      "knowledge_points": ["阅读证据"],
      "objective_ids": ["OBJ-1"],
      "score": 5
    }
  ]
}
```

约束：

- `questions` 至少包含一道题。
- `id`、`type`、`prompt`、`answer`、`difficulty` 和 `score` 必填。
- 选择题必须有不少于两个选项。
- `difficulty` 仅允许 `基础 | 进阶 | 挑战`。
- `score` 必须为正数。
- `estimated_minutes` 和 `total_score` 必须为正数。

### 3.4 多 Agent 协作顺序

```text
课程设计师
  写 lesson_plan_draft.json
        ↓
习题生成器
  读取教案 → 写 exercises_draft.json → JSON 自检
        ↓
Education 产物校验器
  Schema 校验 → 失败则退回习题生成器一次
        ↓
教学审校员
  读取教案与习题 → 检查目标覆盖、答案、年级适配和泄露风险
        ↓
教师预览、采用或转换为学习活动
```

## 4. 教师端习题预览

习题生成器节点折叠时显示题目数量、总分和预计用时。展开后显示：

- 题号、题型、难度和分值；
- 题干和选项；
- 可折叠的参考答案、解析和易错提示；
- 覆盖的教学目标和知识点；
- “添加到学习活动”操作。

前端不显示 Conversation ID、Sandbox ID、workspace 路径和正式产物路径。原始 JSON 仅放在二级折叠区供诊断。

若产物只有路径回执或不可解析文本，界面明确显示“习题结构化失败”，不能以“文本产物”冒充成功题集。

## 5. 学习活动

### 5.1 教师操作

“学习活动”页面提供：

- 新建活动；
- 活动类型：资源、阅读、展示、练习、写作；
- 标题；
- 学生说明；
- 预计用时；
- 可选附件上传；
- 草稿/已发布状态；
- 删除未发布活动。

Agent 习题点击“添加到学习活动”后生成 `practice` 活动：

- `student_payload` 保存题面、选项、分值、知识点和预计用时；
- `teacher_payload` 保存答案、解析和易错提示；
- 不自动保存为作业，也不自动发布。

### 5.2 附件与发布

附件复用现有 Education 材料上传接口，支持 PDF、Word、PPTX 和 HTML。活动通过材料 ID 引用附件，不复制二进制文件。

教师发布课时时，服务端创建固定发布清单，包含：

- 学生活动卡片；
- 学生可见习题；
- 活动附件；
- 课件和其他课程材料。

学生只能读取当前发布版本，不能看到教师答案、解析、草稿活动或未发布附件。

## 6. 编辑器设计

### 6.1 字段标题

字段标题行使用 Flex 布局：

- 左侧是字段名；
- 右侧是“放大编辑”按钮；
- 按钮不使用浮动，不参与标签文本排版；
- 窄屏时仍保持可点击且不遮挡字段名。

### 6.2 放大编辑

对话框使用接近课件编辑器的宽画布：

- 顶部显示字段名称、结构化文本提示和操作条；
- 中间是大尺寸编辑画布；
- 底部显示快捷键、字符数和“完成编辑”；
- `Ctrl/Cmd+S` 仍保存整个课时版本；
- 关闭窗口不会自动保存或发布。

## 7. 错误处理

- 缺少教案产物：习题 Agent 节点失败并说明缺少输入。
- JSON 语法错误：校验器退回原 Agent 修复一次。
- Schema 不合法：返回具体字段路径，例如 `questions[1].answer is required`。
- 修复仍失败：保留诊断文本，禁用“添加到学习活动”。
- 附件上传失败：活动草稿保留，显示可重试错误。
- 发布失败：草稿活动和材料状态不改变。

## 8. 验收标准

1. 字段名称与“放大编辑”按钮在桌面和窄屏均不重合。
2. 放大编辑器具有课件编辑器一致的画布层次，并保持纯文本存储。
3. 新 Agent 运行只接受 `exercises_draft.json`，不能把 `.js` 路径当作成功产物。
4. 教师至少可以预览一道真实题目及其折叠答案。
5. Agent 习题可以转换为草稿学习活动。
6. 教师可以创建带附件的学习活动。
7. 发布后学生可以看到活动和附件，但看不到答案和教师数据。
8. 刷新后草稿/发布状态保持一致。
