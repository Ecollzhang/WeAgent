# Education 展示数据与 Agent 运行稳定性 Bugfix Phase 5 规格

## 1. 阶段目标

本阶段把高中英语固定验收课程从“功能已存在”收敛为“教师能够连续展示并举一反三”的成品数据集，同时只修复本轮实际暴露的最小模块：

1. 作业统一采用一个百分制总分，不让教师在发布时面对产品未采用的量规维度；
2. 数字 PDF 可以上传、提取、作为作业附件发布，并在学生端下载；
3. 题库既可按阅读材料题组浏览，也可按课程课时组织；
4. 材料下的多道子题可以收起，长题组不再永久撑高页面；
5. 教师可以在试卷库中明确选择已发布题目后组卷；
6. 固定账号中的三个课时都有足够的真实题目，核心功能均有可展示案例；
7. DeepSeek/Codex Agent 不再被全局提示词要求调用运行环境没有提供的 `bash`、`run_command`、`weagent-report` 或 Provider 原生 `education_action`；
8. 课时工作台右上操作采用 2×2 布局，移除常驻的“有未保存更改”标签，但保留离开与发布时的数据保护提醒。

本阶段不重写现有课程、作业、版本、资产、试卷或聊天模型，不清理历史 Docker 会话。

## 2. 产品决定

### 2.1 作业评分采用单一百分制

教师新建作业时只看到：

> 百分制总分 100；不拆分评分子项；AI 只提供建议，最终分数由教师确认。

约束如下：

- Education 前端新建作业固定提交 `max_score=100`；
- 新建与本轮固定演示作业使用空的 `evaluation_json`，不展示观点、证据、语言等分项；
- 提交详情只保留一个“教师反馈”和一个最终分数；
- 后端继续兼容历史量规数据，避免破坏已有课程、旧版本和 API 使用方，但它不再是当前产品入口的默认交互。

### 2.2 PDF 发布不是“上传成功”即验收成功

完整验收链为：

```text
教师选择真实 PDF
  → 二进制写入 edu_assets
  → AssignmentImportJob 记录来源和处理状态
  → pypdf 提取数字 PDF 正文
  → 教师得到可编辑草稿
  → 作业版本引用 source_asset_ids
  → 发布时资产变为 course_published
  → 学生读取作业并下载完全相同的 PDF 字节
```

扫描图片继续走 RapidOCR fallback。数字 PDF 不应先栅格化再 OCR。

### 2.3 题库的两种组织方式

教师可在题库顶部切换：

- **按材料**：展示阅读材料卡片及其多道子题，适合“一篇文章多问”；
- **按课时**：选择一个课时，只查看该课时的材料与独立题。

数据模型增加可空的 `lesson_id`：

- `edu_assessment_stimuli.lesson_id`；
- `edu_assessment_items.lesson_id`。

材料题的课时默认继承材料课时。显式传入与材料不同的课时必须被服务端拒绝。旧数据允许为空，以维持兼容。

材料身份与材料版本必须分离：材料创建新版本后，引用旧材料版本的题目仍然属于同一材料卡片，不能从题组界面消失。

### 2.4 手动组卷必须先看到可选题

试卷库的“手动选题组卷”打开独立选择窗口：

- 只列出已发布题目；
- 可按课时筛选；
- 每道题显示名称、课时、题型、分值和题干；
- 支持选择当前筛选下的全部已发布题目；
- 显示已选题数；
- 选择完成后再进入试卷名称、用途和时长设置。

试卷版本仍冻结题目的 `published_version_id`，不跟随题库后续编辑漂移。

## 3. Agent 超时根因与修复

### 3.1 根因

DeepSeek 通过 Codex Responses 兼容层运行时，系统为了兼容该 Provider 已关闭：

- `unified_exec`；
- `shell_tool`；
- goals 和其它不兼容的原生工具。

但 `AgentRuntime._runtime_instruction()` 仍无条件要求每个 Agent：

- 先调用 Bash；
- 每一步调用 `weagent-report`；
- 用 Shell 写入产物文件。

模型因此重复尝试 `run_command` 或 `bash`，路由器持续返回 `unsupported call`，学情分析师等任务直到 600 秒超时。课件任务本身有服务器 fenced-block fallback，所以可能最终生成成功；并发的学情任务错误却同时出现在聊天流中，造成“PPT 失败”的表象。

进一步真实回归还确认：DeepSeek Responses 兼容层同样不会注册 Provider 原生 `education_action`。仅禁止 Shell 只能消除超时，不能让依赖业务写入的学情 Agent 完成落库；第一次回归因此正确结束为 `partial`，而不是伪造成功。

### 3.2 最小修复

不开放任意 Shell。Provider Runner 显式声明是否支持原生 Shell：

- 原生 Claude/OpenAI Codex 继续使用现有工具协议；
- DeepSeek/Codex 使用无工具运行协议，禁止 `bash`、`run_command`、`run_command_safe`、`weagent-report`、`update_plan` 和虚构工具；
- 运行进度由服务器 heartbeat 和工作流节点状态自动提供；
- 大型课件产物只允许返回两个精确的受控文件块：`slide_document.json` 和 `preview.html`；
- 可信服务器把文件块写入 Agent 私有工作区，执行 schema/视觉校验，再调用固定业务终结器；
- 学情分析师只返回严格的 `{"refresh":true}` 请求；可信服务器先读取真实课程成员，再以受限 Agent grant 调用 `edu.student_insight.refresh`，审校 Agent 只接收真实终结结果；
- Agent 不能声称自己执行过文件系统工具。

这消除了矛盾提示词，同时保持沙箱权限边界不变。

## 4. 固定展示课程

课程：`高一英语·叙事阅读与写作（真实案例）`

固定入口：

- 教师账号：`edu_teacher_phase4_0802_authentic`；
- 学生账号：`edu_student_1_phase4_0802_authentic`；
- 课程 ID：`1821bf81-485d-4c1a-94e3-b90936bceb8d`。

演示密码只由本地 UAT 环境提供，不写入代码、规格或 Git。

### 4.1 已持久化案例

| 功能 | 演示数据 |
|---|---|
| 课程与课时 | 1 门课程，3 个已发布课时 |
| 多用户 | 1 位教师，7 位学生 |
| 作业闭环 | 3 份已发布百分制作业，15 份真实提交与教师反馈 |
| PDF 作业 | 2 页真实英语读写作业，数字正文可提取，学生可下载 |
| 题库 | 1 个公共领域阅读材料题组，11 道题，覆盖 6 种题型 |
| 按课时组织 | 课时 1 有 6 道题，课时 2 有 3 道题，课时 3 有 2 道题 |
| 试卷库 | 2 份已发布试卷，其中一份用于演示课时筛选和手动选题 |
| 模拟考试 | 固定学生有 2 份 7 题考试记录；最新一次为真实作答，客观题 21/21，主观题待教师复核 |
| 知识库 | PDF 阅读写作讲义作为学生可见课程资源 |
| 学情与弱点 | 7 份学生画像；固定学生有 3 个证据支持的弱点项 |
| 思维导图 | 1 张可编辑、可着色、带关系边的课程导图 |

阅读材料来自 O. Henry 的公共领域短篇 *The Gift of the Magi*，来源记录为 Project Gutenberg eBook #7256。题目包含单选、多选、判断、填空、简答和写作，不使用虚构教材内容。

## 5. UI 规格

### 5.1 作业发布弹窗

- 文件导入、作业名称、要求、课时和任务侧重保持不变；
- 原可编辑的“作业满分”数字输入替换为固定百分制说明卡；
- PDF/照片仍可选择“附件发布”或“识别为可编辑作业”。

### 5.2 题组卡片

- 材料正文使用独立折叠区；
- 配套题目使用独立的“展开题目/收起题目”控制；
- 题组卡片显示所属课时和来源；
- 独立题显示课时标签。

### 5.3 课时工作台操作区

四个位置组成 2×2：

```text
已发布/草稿       Agent 协作生成
保存新版本        发布给学生
```

“有未保存更改”不再常驻。离开路由或发布时仍根据 dirty state 二次确认，防止教师误丢内容。

## 6. 验收标准

### 6.1 自动化

- DeepSeek runtime instruction 中不存在强制 Shell 或 `weagent-report`；
- 课件 prompt 明确要求两个 fenced file blocks 和可信运行时写入；
- 新建材料和题目可写入、读取并校验 `lesson_id`；
- 材料新建版本后，旧版本关联的题目仍在同一题组；
- 前端存在百分制说明、课时组织、手动选题、题组收起和 2×2 操作布局；
- Vue 生产构建完成。

### 6.2 真实 UAT

1. 固定教师账号登录并打开课程；
2. 三个作业均显示满分 100，且无评分子项；
3. PDF 导入状态为 `review_required`，提取器为 `pdf_text`；
4. 学生端能看到 PDF 关联作业与知识资源；
5. 下载响应为 `application/pdf`，下载字节 SHA-256 与上传源文件一致；
6. 题库按每个课时至少显示 2 道题；
7. 试卷库手动选择题目并生成冻结版本；
8. 新建 Agent 运行日志不再出现 `unsupported call: run_command` 或 `unsupported call: bash`；
9. 课件生成后得到新的结构化课件版本、HTML 预览和导出入口。

## 7. 兼容与隔离边界

- 二进制仍由 Education 数据库存储，Docker 会话不是课程数据真值；
- 课程、课时、资产、题目、试卷、作业、提交和画像都继续按 course membership 隔离；
- 学生只能读取 `course_published` 资产和已发布题目/试卷版本；
- 历史量规继续可读，但新产品入口不再生成它；
- 历史 Docker 会话不因本阶段重建镜像而删除；只有新会话使用新沙箱镜像；
- `.env`、Token、密码和 Agent 授权信息不得写入数据库产物、聊天可见 prompt 或 Git。
