## 1. 本阶段目标

本阶段要把 Education 中已经存在但仍然彼此割裂的“课程内容”收束成一个可维护的闭环：

1. 教师在“PPT 与课件”上传或生成的文件，与教学空间中对应课时的“课件和材料”是同一份持久资产的不同视图，不再复制、不再串入作业附件。
2. 教师可在两个教师入口统一执行“教师可见、学生可见、删除”；学生只读取已经发布的内容。
3. 课程知识中心不只有手工录入入口，还能通过受控 Agent 生成题库、组卷，并把教师上传或联网采纳的资料沉淀到课程知识库。
4. 学生思维导图从“整门课程的静态树 + JSON 文本编辑”升级为“课程内可建立多张课时导图、可拖动、可连线、可保存版本”的可视化工具。
5. PPT 工作台、课程页头、AI 记录和作业页面在多课程、多课时、长内容场景下仍然稳定、清晰、可管理。

这不是重新建立一套 LMS，也不是把聊天、Sandbox 文件或临时路径当成业务数据。MySQL 中的 Education 业务对象和持久资产仍是权威来源；Agent 只通过受控工具写入草稿。

## 2. 当前实现结论

### 2.1 课件柜为什么出现作业 PNG/PDF

当前 `EducationAsset` 已经持久化 `course_id`、可选 `lesson_id`、`purpose`、`visibility_scope` 和二进制内容，具备成为唯一资产源的基础。

问题来自两个过宽的约定：

- 作业文件导入在 `content_routes.py` 中把 PDF/图片保存为 `purpose="course_material"`；
- `CoursewareLibrary.vue` 又把 `courseware`、`lesson_material`、`course_material`、`agent_output` 全部视为课件。

因此截图中的 `uat-photo-assignment.png` 和 `uat-reading-assignment.pdf` 不是同步错误，而是“作业来源文件被错误分类后，被课件柜的宽泛过滤规则纳入”。

当前资产接口还只有上传、查询、下载和修改标题/可见性，没有删除接口；课件柜菜单也只有下载和单向“发布给学生”，不能撤回为教师可见。

### 2.2 课程知识中心已经有什么、还缺什么

已有能力：

- 题目稳定身份与不可变版本；
- 教师手工创建题目、发布题目；
- 从已发布题目冻结试卷草稿并发布；
- 上传知识文件，保存为 `EducationAsset + KnowledgeResource`；
- `SearchProvider → ContentFetcher → Retriever → Reranker` 的服务端接口骨架和搜索 Provider fallback 控制流；
- Agent 侧题库写入、组卷和知识检索工具。

缺失能力：

- 题库和试卷库页面没有明确的“Agent 生成题目 / Agent 组卷”产品入口；
- 搜索管线只有契约和基础 HTML 清洗器，没有完整 Provider、远程文件下载、来源审查、教师采纳和知识库入库闭环；
- 搜索结果摘要仍不能当成网页或文档正文；
- PDF、DOCX、PPTX、扫描图片等资料缺少统一的结构化抽取适配器和可观测的索引状态。

### 2.3 学生思维导图目前到底是什么

当前实现是“课程级个人导图”：

- 一张导图归属于 `course_id + owner_user_id`，没有 `lesson_id` 或范围类型；
- 可创建多张导图，但规则生成会把整门课已发布的所有课时和知识资料平铺到一个课程根节点下；
- 数据结构只有嵌套 `tree_json`，没有独立关系边；
- 页面用递归 Vue 组件渲染静态树，编辑方式是直接修改 JSON；
- 不支持节点拖动、重新挂接、缩放/平移、撤销/重做、关系连线。

所以它目前不是 XMind 式编辑器。用户看到的“课程思维导图”只是整个课程来源的可追溯树形摘要。

### 2.4 PPT 多课程/多课时为什么容易出错

课程选择同时由以下位置驱动：

- `EducationCourseContext` 根据路由、当前课程和角色自行恢复；
- 页面自身 `bootstrap()` 再调用 `ensureRoleCourse()`；
- `course.id` watcher 再次加载数据；
- 切换课程后路由 query 又触发一次恢复。

这造成路由和 Vuex 同时作为课程真值，并存在并发旧请求覆盖新课程数据的窗口。当前 PPT 页面还同时展示课时下拉框和完整课时列表，结构化版本默认混合所有课时；课程较多后既拥挤，也增加了误操作概率。

“全部课程偶发报错”需要在多课程 UAT 中复现具体响应，但上述双重初始化和未取消的旧请求已是明确的契约缺陷，不能只靠 catch 后显示“课程不可用”。

### 2.5 作业为什么会出现超长卡片、且不能编辑

- 教学空间的作业卡片直接渲染完整 `instruction_json`，没有固定正文区域、截断或滚动边界；
- 作业详情同样直接以 `white-space: pre-wrap` 输出全文；
- 后端只有创建、读取和发布作业接口，没有更新作业或作业内容版本接口；
- 教师详情页因此只能查看内容和发布，不能像邮件编辑器一样维护正文、附件、评分标准和设置；
- `EmbeddedAgentRecord` 只要存在 `business_route` 就显示“返回业务页面”。当当前页面本身就是该业务页面时，点击被组件主动忽略，形成“按钮没反应”的假入口。

### 2.6 教师端侧栏“重影”的根因

`WorkspaceSwitcher` 把服务端的 `ws.icon` 原样渲染到固定宽度 18px 的文本容器中。Education Workspace 的 icon 值为 `education` 时，整串英文会从图标容器溢出，与工作空间名称和“教师”标签重叠。该问题与浏览器缓存、阴影或 z-index 无关，是图标字段缺少映射和内容约束。

## 3. 问题与最小解决方案

## BUG-301：课件柜与课时材料不是同一资产视图，且作业附件串入课件柜

### 目标行为

教师在以下两个位置看到的是同一份 `EducationAsset`：

- `PPT 与课件 → 02 课件文件柜`：课程级资产柜，可按课时筛选；
- `教学空间 → 对应课时 → 课件和材料`：只显示该课时绑定的课件和材料。

任何一侧修改可见性或删除后，另一侧刷新应立即得到相同结果。学生端只显示 `course_published` 的对应课时内容。

### 最小数据方案

本阶段不新建第二套文件表，也不复制二进制内容：

1. 继续以 `EducationAsset` 为唯一二进制资产。
2. 规范 `purpose`：
   - `courseware`：PPT/PDF/DOCX/HTML 等课件；
   - `lesson_material`：课时阅读材料、活动材料；
   - `assignment_source`：作业 PDF、照片及 OCR 来源；
   - `knowledge_resource`：知识库来源；
   - 其余 `roster`、`student_submission` 保持隔离。
3. 上传课件或课时材料必须传 `lesson_id`；当前前端 `uploadAsset` action 需要补齐该字段。
4. 课件柜只读取 `courseware` 和 `lesson_material`；不再用通用 `course_material` 或无类型的 `agent_output` 兜底。
5. 对现有数据执行定向迁移：凡被 `AssignmentImportJob` 或 `Assignment.source_asset_ids` 引用的 `course_material` 迁为 `assignment_source`；不能仅按扩展名猜测。
6. 历史 Agent 课件只有在能由正式内容对象证明属于 `slide_document` 时迁为 `courseware`。

如果未来需要一份文件绑定多个课时，再增加关系表；本阶段一份资产绑定零个或一个课时，避免为了未出现的需求扩大迁移面。

### 统一的三个教师操作

两个教师入口都提供完全相同的菜单：

1. **教师可见**：写入 `course_teacher`，也承担从学生端撤回的“取消发布”；
2. **学生可见**：写入 `course_published`；
3. **删除**：调用新的 archive API，执行软删除。

学生端没有可见性和删除菜单，只能预览/下载已发布内容。

删除采用以下约束：

- 被已发布作业、知识资源或正式内容版本引用时返回 `409 asset_in_use`，同时返回依赖对象摘要；
- 没有正式依赖时把 `status` 改为 `archived`，不立即物理清除数据库 blob；
- 后续单独做无引用归档资产的保留期清理，不在本阶段实现硬删除。

### API 最小变更

- `GET /courses/:course_id/assets?purpose=&lesson_id=&visibility_scope=`：服务端过滤，不让各页面自行宽泛筛选；
- `PATCH /assets/:asset_id`：保留改标题/可见性；
- `DELETE /assets/:asset_id`：软删除并进行引用检查；
- 所有学生查询仍由服务端强制限制为 `course_published`。

## BUG-302：题库、试卷库和知识库缺少 Agent 生成与联网资料采纳闭环

### 页面入口

课程知识中心仍保留三个明确的库：

- **题库**：手工新建、Agent 生成题目、校验、保存草稿、教师发布；
- **试卷库**：手工选题组卷、Agent 按范围/难度组卷、保存草稿、教师发布；
- **知识库**：教师上传、本地解析、联网搜索并采纳、索引状态、来源追溯。

题库 Agent 输入只要求教师选择课程/课时、知识点、题型、数量和难度，不要求教师编写系统 Prompt。Agent 必须调用正式题库工具写入草稿；聊天文本和沙箱文件不算完成。

组卷 Agent 从已发布题目版本中选择并冻结版本，不临时复制题目文本。若题库不足，应返回缺口报告，而不是伪造“已组卷”。

### 联网知识 Agent 管线

联网流程固定拆为：

```text
SearchProvider A/B
  → 候选 URL、标题、搜索摘要
  → URL/版权/类型初筛
  → ContentFetcher / RemoteFileFetcher
  → 正文清洗或文档解析
  → Retriever
  → Reranker
  → 教师预览与采纳
  → EducationAsset + KnowledgeResource
  → 异步索引
```

约束：

1. 搜索结果的 `excerpt/content` 只作为发现元数据，绝不当作网页全文入库。
2. Provider A 失败、超时或无结果时才切换 Provider B，并在结果中记录 fallback 诊断。
3. 远程下载必须经过 SSRF 安全层：只允许 HTTP(S) 公网地址，限制 DNS/IP、重定向次数、响应体大小、内容类型和超时。
4. PDF/DOCX 等远程文件先下载到受控内存/临时区，完成 MIME、大小和恶意内容检查后，才写入 `EducationAsset`。
5. 每个采纳资源保存 `source_url`、抓取时间、标题、作者/站点、许可说明、SHA-256 和清洗器版本。
6. 付费墙、登录页、robots/许可不明确或正文抓取失败的候选不能自动采纳。
7. Agent 产出的 PDF/Word 是由规范结构化内容导出的教学产物，不得冒充外部来源文献。
8. 所有生成和采纳结果默认教师草稿，不自动发布给学生。

### 借优而非自造

- HTML 正文抽取优先通过适配器试用 [Trafilatura](https://trafilatura.readthedocs.io/en/stable/)；它负责从已安全下载的 HTML 中提取正文和元数据，不负责绕过安全边界。
- PDF、DOCX、PPTX、HTML 和图片的统一结构化转换优先评估 [Docling](https://docling-project.github.io/docling/)；以独立可选解析 Worker/能力包接入，避免把较重依赖塞进 Education HTTP 进程。
- 现有 OCR 继续作为扫描图片/PDF fallback；解析器必须按能力注册并输出统一的 `extraction_status/warnings`。

以上库都放在接口适配层，业务模型不依赖具体第三方返回格式；实际版本必须在实现阶段经过最小样本 spike 后锁定。

## BUG-303：课程思维导图不是课时化、可拖动的可视化编辑器

### 产品模型

一门课可以有多张导图，导图增加范围：

- `course`：课程总览，可连接多个课时与跨课时知识点；
- `lesson`：绑定一个课时，用于该课时的阅读结构、写作方法、词汇/主题关系；
- `custom`：学生自定义选择若干课时和知识资料。

课程页面提供“按课时创建导图”和“课程总览导图”，而不是每次把整门课所有来源平铺到同一根节点。

### 规范数据结构

在兼容现有 `tree_json` v1 的基础上增加 v2：

```json
{
  "schema_name": "education_mind_map_v2",
  "scope_type": "lesson",
  "lesson_ids": ["..."],
  "root": { "id": "...", "label": "...", "children": [] },
  "relations": [
    { "id": "...", "from": "...", "to": "...", "label": "因果", "type": "cross_link" }
  ],
  "view": { "direction": "right", "theme": "education_clear" }
}
```

- 树仍表达父子结构；`relations` 表达非父子的知识关系；
- 来源引用仍由服务端校验课程权限；
- 每次保存创建不可变版本，当前版本指针更新；
- 旧 v1 树可无损包装为 v2，不要求一次性重写所有历史版本。

### 编辑体验

MVP 至少包含：

- 新建/重命名/删除节点；
- 拖动排序和重新挂接父节点；
- 画布缩放、平移、居中；
- 增加/删除关系线及关系标签；
- 展开/折叠；
- 撤销/重做；
- 保存新版本、查看版本时间和恢复为新版本；
- 导出 PNG/SVG/HTML；
- Agent 基于选定课时生成草稿后，学生继续可视化编辑。

推荐以 [Mind Elixir](https://github.com/SSShooter/mind-elixir-core) 为第一候选：它是框架无关的 JavaScript 思维导图核心，官方能力包含拖放、节点编辑、撤销/重做、节点连接和导出。当前前端是 Vue 2.7，因此用薄适配组件直接挂载框架无关核心，不引入 Vue 3 专用封装。`jsMind` 可作为失败时的轻量备选。

### 明确不做的 XMind 范围

本阶段不承诺：实时多人共同编辑、完整 `.xmind` 双向兼容、鱼骨图/时间轴/组织结构图等全部布局、桌面客户端、无限画布附件系统。先完成课程与课时的可视化学习闭环。

## BUG-304：PPT 工作台的课程/课时选择与三个区块逻辑不稳定

### 新的页面逻辑

页面只有一个课程上下文来源：规范化后的路由 `courseId`。Vuex 是缓存，不再与路由竞争。

1. **01 从课时继续制作**
   - 当前课程内用紧凑课时选择器选择一个课时；
   - 显示所选课时的教案、目标、活动、知识来源摘要；
   - “继续编辑 / AI 生成课件”始终针对所选课时；
   - 不再同时永久展开整门课的完整课时列表。
2. **02 课件文件柜**
   - 默认按所选课时过滤；
   - 可切换“当前课时 / 全课程”；
   - 修改权限、删除和上传结果同步到教学空间对应课时。
3. **03 结构化课件版本**
   - 默认只显示所选课时版本；
   - 可切换全课程历史；
   - 保留结构化编辑、逐页检查和多格式导出。

### 稳定性要求

- 切换课程时使用请求序号或 AbortController 丢弃旧课程返回；
- 页面初始化只调用一次 `ensureRoleCourse`，课程上下文组件不重复拉相同数据；
- 路由中的课程不存在、角色不符时显示可恢复空状态并保留可选课程，不跳到错误角色页面；
- 记忆 `courseId → lastLessonId`，再次返回该课程恢复最后课时；
- “全部课程”只回到课程列表，不清空用户身份，不触发错误提示。

下一轮 UAT 必须至少建立两门教师课程、每门三个课时，并额外用一种非当前风格生成课件。风格只允许现有 `clear_classroom`、`paper_annotation`、`storybook`、`dark_focus`，不得让 Agent 任意生成 CSS 主题。

## BUG-305：AI 生成记录位置和课程页头布局不合理

### AI 生成记录

教学空间中的记录条放在“课程页头/课程上下文”与“课时、作业、成员、学情、知识中心标签”之间。

当前记录只绑定“AI 名单导入”，需要改为课程级最新记录聚合：

- 默认显示最近一次与当前课程有关的产品运行；
- 可按课时和类型查看历史：教案、课件、习题、名单、学情；
- 摘要显示任务、课时、状态、时间和产物；
- “返回本次聊天”进入对应会话；
- “预览最新产物”进入正式业务对象；
- 当前已经位于 `business_route` 时不显示“返回业务页面”，杜绝无反应按钮。

### 页头布局

桌面端改为可换行的两层网格：

- 左侧：课程标题与学科说明，标题最多两行，完整标题通过 tooltip 查看；
- 中间：紧凑的课程上下文，设置合理最大宽度；
- 右侧：教师身份、改名、邀请、新建课时、发布作业采用 2×2/自动换行按钮组；
- 低于 1280px 时，课程上下文与操作区进入第二行；
- 不允许标题被挤成狭窄竖列，也不允许上下文条无限拉长。

## BUG-306：作业卡片过长、教师不能编辑、详情层级不清

### 列表卡片

- 卡片保持统一最小/最大高度；
- 标题最多两行；
- 正文区域显示固定 4 行，超出时出现可访问的滚动/展开全文入口；
- 控制字符在保存前清理，只保留换行和制表符等允许字符；
- 极长 OCR/Agent 内容不能把整个课程网格撑高。

### 教师详情编辑

“作业内容”页增加明确的“编辑”模式，复用现有邮件式富文本编辑能力：字体、字号、粗体、斜体、下划线、对齐、列表、缩进、撤销/重做、链接等。教师可维护：

- 标题、任务类型、正文；
- 附件；
- 评分标准；
- 满分、最大提交次数、订正设置；
- 发布状态。

正文编辑器使用固定可视高度并滚动，不再像长代码块无限增长。

### 版本和发布语义

- 草稿可直接修改；
- 已发布作业不能原地改写学生正在使用的版本；
- 编辑已发布作业时创建新的教师草稿版本；
- 学生继续看到上一个已发布快照，直到教师再次发布新版本；
- 发布前若有未保存更改，弹出“保存并发布 / 放弃更改 / 取消”；
- 保留 `Ctrl/Cmd + S` 保存快捷键。

这要求增加 Assignment 内容版本或等价的发布快照，不能只在现有表上增加一个 PATCH 后直接覆盖。

### 详情间距

- “作业分析”标题与最高/最低/平均分卡片之间至少保留 24px；
- 分数卡片与分析说明之间至少保留 24px；
- “作业内容”正文、附件、评分标准拆成独立 section，section 间距 24px；
- PDF/图片附件使用独立附件卡片，不紧贴评分标准标题。

## BUG-307：教师 Workspace 图标字符串溢出形成重影

### 最小解决方案

1. 前端只接受受控 icon key，通过映射输出 Element UI icon class 或单个 glyph。
2. `education` 映射为 `el-icon-reading`，不直接渲染字符串。
3. 未知值回退 `el-icon-folder`。
4. 图标容器增加 `overflow: hidden`、固定行高和 `aria-hidden=true`。
5. 工作空间名称与身份标签继续独立截断，不能依赖图标覆盖来压缩。

服务端长期应返回 icon key，而不是自由文本；前端仍需防御未知历史值。

## BUG-308：页面上存在“看似可点但不会产生状态变化”的入口

除“返回业务页面”外，本阶段统一检查资产三点菜单、AI 记录、课程选择和课时选择：

- 当前路由与目标路由相同时隐藏返回按钮；
- 没有正式 `object_id/version_id` 时不显示“预览最新产物”；
- 删除、权限修改、发布等操作成功后必须刷新同一 canonical query；
- 失败提示包含稳定 `error_code`，不能只显示 Server Error；
- 重复点击写操作使用幂等 key 或禁用态，避免重复版本。

## 4. 模块与兼容边界

### 4.1 保持不变

- Education 服务继续独立运行在核心聊天服务之外；
- 核心聊天负责会话与 Sandbox 协作，Education 数据库负责业务事实；
- 用户文件、课程、版本、发布状态都不依赖 Docker 容器生命周期；
- Agent 不直接得到 `course_id/user_id/token` 等越权参数，由服务端授权范围注入；
- 所有 Agent 结果默认草稿，教师发布是最终业务动作；
- `.env` 只用于本地 UAT，继续保持 Git ignore，不在日志和文档中记录 token。

### 4.2 明确不做

- 不把 WeAgent 改造成完整通用 LMS；
- 不复制聊天附件到新的临时文件柜；
- 不允许任意网页整站爬取、绕过登录/付费墙或无来源入库；
- 不让学生改课件权限或删除教师资产；
- 不把 JSON/HTML 沙箱文件当成已采纳业务产物；
- 不在本阶段做实时多人导图协作和完整 XMind 替代品。

## 5. 实施阶段建议

### Phase 3A：确定性 Bugfix 与统一资产视图

范围：BUG-301、BUG-304、BUG-305、BUG-307、BUG-308，以及 BUG-306 的卡片高度/间距。

特点：尽量只改现有资产接口、筛选规则、课程上下文和 CSS；先消除串柜、重影、无反应按钮和课程切换竞态。

### Phase 3B：作业可编辑与知识 Agent 产品入口

范围：BUG-302 的题目生成/组卷入口，BUG-306 的作业版本、富文本编辑和重新发布。

特点：需要数据库迁移和正式工具契约，必须补单元、API 和角色权限测试。

### Phase 3C：联网知识采纳与可视化思维导图

范围：BUG-302 的远程搜索/抓取/解析/采纳，BUG-303 全部。

特点：先对第三方库做隔离 spike，再接入适配层；导图编辑器和文档解析 Worker 不侵入核心业务模型。

阶段之间不要求用户逐阶段人工验收；按既定约定，仅在本 Phase 3 全部完成并完成真实 UAT 后交给用户验收。中途缺陷写入实施记录并继续推进，除非出现权限、数据破坏风险或确实无法自行决定的产品冲突。

## 6. 验收数据集

实施完成后使用新的隔离 UAT 数据，不复用脏历史课程：

- 1 个教师账户、1 个学生账户；
- 2 门课程：高中英语、小学语文；
- 每门至少 3 个课时；
- 每门至少 2 个课件文件、1 个课时材料、1 个作业附件、1 个知识资料；
- 至少 8 道题、2 份试卷；
- 至少 1 个超长作业正文；
- 至少 2 张课时导图和 1 张课程总览导图；
- 至少 2 种课件风格。

测试资料优先使用自建内容、公共领域文本或明确允许使用的开放教育资源；保存 URL 和许可信息。不得为了 UAT 把来源不明的网上题目直接发布给学生。

## 8. 测试与完成门槛

完成必须同时满足：

1. 后端模型/迁移、Service、Route 单元测试通过；
2. 资产 purpose、权限、软删除和引用冲突有 API 测试；
3. 作业草稿/发布快照和并发更新有测试；
4. Agent 题目、试卷、知识采纳工具有 schema 和幂等测试；
5. 思维导图 v1→v2 兼容、节点/关系校验、权限和版本测试通过；
6. 前端 build、相关组件测试和浏览器 console/network 检查通过；
7. 使用真实教师/学生账户完成上述 UAT；
8. 真实浏览器逐项截图或保留可复核的测试记录；
9. Git diff 无敏感信息，`.env` 未被跟踪；
10. 没有以“部分完成”“已降级为文本”“只生成沙箱路径”冒充成品结果。

## 9. 最终产品判断

本阶段完成后的核心体验应是：教师围绕课程和课时管理一份真实资产，生成课件、题目和试卷，上传或受控采纳知识资料，发布作业；学生看到教师正式发布的课件和作业，并可围绕一个或多个课时构建自己的可视化思维导图。聊天与多 Agent 协作提供生成、分析和追溯能力，但所有可验收结果都回到 Education 的正式业务对象中。
