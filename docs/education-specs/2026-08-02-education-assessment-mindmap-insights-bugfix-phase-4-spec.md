## 1. 本阶段目标

Phase 4 不增加新的一级领域，也不重做 Education 架构。本阶段把 Phase 3 已经具备的数据对象和页面入口补齐为可理解、可编辑、可验收的产品闭环：

1. 题库同时支持“阅读材料 + 多道子题”的题组和独立题，覆盖高中英语、小学语文需要的多种题型，而不是把题库等同于单选题列表。
2. 教师可以预览试卷，可以编辑已有题目和试卷；所有修改仍通过不可变版本完成，不直接覆盖学生正在使用的已发布版本。
3. 学生思维导图支持双击编辑、受控颜色、有效的同级排序和真正的内容居中；查看状态不再留下遮挡画布的空白栏。
4. 教师发布成绩与反馈后，学生的作业弱点自动更新；学生不必理解“快照刷新”或额外启动 Agent 才能看到结果。
5. 批改工作台只保留一个面向学生的“教师反馈”，AI 建议可收放；没有真实锚点的伪批注入口下线。
6. “学生画像与评估”明确拆成“成绩总览”和“学生画像”两种模式。成绩总览按作业查看分布，并提供课程级作业平均分趋势；学生画像首屏一行三人、按三人加载更多并可进入详情。
7. Education 页头、教学空间操作区和通用弹窗形成统一的宽度、圆角、留白和内部滚动规范。

### 2.1 当前学生账号的真实页面证据

使用现有学生验收账号复核当前课程：

- 思维导图页面处于编辑状态时显示右侧节点检查器；组件源码证明查看状态仍保留第二列，因此空白栏是布局契约错误，不是用户误操作。
- 当前课程的作业弱点页面显示 `0 条作答证据` 和“数据不足”。该页面只读取最近一次快照，没有在教师发布反馈后自动检查证据指纹。

## 3. 方案选择

### 3.1 题组数据方案

#### 方案 A：把文章重复放入每道题的 `source_context`

优点是改动最少。缺点是文章会重复存储和渲染，修改文章时会产生多个不一致版本，试卷预览也无法可靠判断哪些题属于同一篇材料。

结论：不采用。

#### 方案 B：只在前端按相同文本临时分组

优点是不迁移数据库。缺点是分组身份不稳定，Agent、API、试卷冻结和版本回溯仍然不知道题组是什么。

结论：不采用。

#### 方案 C：版本化阅读材料 + 题目版本引用（推荐）

新增稳定的阅读材料身份和不可变材料版本。题目版本可选引用一个材料版本；没有材料的语法题、写作题仍作为独立题存在。试卷冻结题目版本时，题目自然携带同一个冻结材料版本。

这是唯一同时满足“借优后的标准题组语义、版本可追溯、编辑不污染已发布内容”和中等开发量的方案。

### 3.2 弱点更新方案

- 只保留手动刷新：实现最少，但用户会持续遇到“已批改却没有弱点”。不采用。
- 教师发布反馈时同步重建学生弱点：即时，但需要跨模块调用。采用为主路径。
- 学生读取时比较证据指纹并补建：可修复历史遗漏和偶发失败。采用为兜底。

最终方案是“`FeedbackReleased` / `MockExamSubmitted` 触发投影 + GET 指纹兜底”，不依赖模型调用。

### 3.3 思维导图颜色方案

- 不允许节点保存任意 CSS、任意十六进制颜色或 HTML。
- 只保存 `color_token`，由前端映射到 Education 受控色板。
- 首期提供 8 个有足够文字对比度的色板令牌，并保留“按层级自动配色”。

## 4. BUG-401：阅读材料题组与多题型题库

### 4.1 产品结构

题库包含两种一等内容：

1. **材料题组**：一篇阅读材料、说明或图文材料，下面挂多道子题。
2. **独立题**：不依赖材料的词汇、语法、填空、简答或写作任务。

“一篇文章 + 多问”是高中英语和小学语文阅读的默认生成方式，但不是所有题目的强制形式。写作任务、语言运用题和部分语法题可以独立存在，也可以引用同一材料形成读写迁移题组。

### 4.2 数据模型

新增：

- `AssessmentStimulus`
  - `id`
  - `course_id`
  - `title`
  - `stimulus_type`：`reading_passage`、`image_text`、`reference_material`
  - `owner_user_id`
  - `current_version_id`
  - `published_version_id`
  - `status`
- `AssessmentStimulusVersion`
  - `id`
  - `stimulus_id`
  - `version_number`
  - `content_json`：正文、段落、必要的图片资产引用；不保存任意可执行 HTML
  - `source_refs`
  - `language`
  - `word_or_character_count`
  - `checksum`
  - `created_by_user_id`
  - `created_at`

扩展 `AssessmentItemVersion`：

- `stimulus_version_id`：可空；指向冻结的材料版本。
- `stimulus_order`：材料题组内的显示顺序。

扩展题目类型：

- `single_choice`
- `multiple_choice`
- `true_false`
- `fill_blank`
- `short_answer`
- `writing`

不新增含义相近的 `reading_question` 类型；是否属于阅读题由 `stimulus_version_id` 表达，避免把“题型”和“材料关系”混为一谈。

### 4.3 草稿与发布指针

当前题目只有 `current_version_id`，已发布题目创建新版本后会立即把学生侧指向新版本。为保证编辑安全：

- `current_version_id` 表示教师当前草稿版本。
- 新增 `published_version_id` 表示学生和正式组卷可使用的版本。
- 编辑已发布题目只创建新草稿版本，不改变 `published_version_id`。
- 教师点击发布后，才把 `published_version_id` 更新为当前草稿版本。
- 试卷组卷只允许冻结题目的 `published_version_id`。
- 历史试卷继续读取自己冻结的题目版本和材料版本，不随题库后续编辑变化。

材料和试卷采用同样的草稿/已发布双指针语义。

### 4.4 教师题库界面

题库默认按材料分组显示：

```text
材料卡片：标题 / 类型 / 字数 / 来源 / vN / 草稿或已发布
  ├─ 第 1 题 · 单选 · 难度 · 分值 · 编辑
  ├─ 第 2 题 · 填空 · 难度 · 分值 · 编辑
  ├─ 第 3 题 · 简答 · 难度 · 分值 · 编辑
  └─ 第 4 题 · 写作迁移 · 难度 · 分值 · 编辑

独立题
  ├─ 词汇题
  └─ 独立写作任务
```

要求：

- 材料正文默认折叠为摘要，点击展开全文。
- 支持按题型、状态、课时、知识点和难度筛选。
- 题组可以整体勾选组卷，也可以选择其中部分题目。
- 题目卡显示题型名称；非选择题不渲染空选项区。
- 教师答案和解析默认收起，学生 API 永远不返回答案。

### 4.5 动态题目编辑器

“新建题目”和“编辑题目”共用同一编辑器：

- 先选择独立题或所属材料，再选择题型。
- 单选、多选显示纯文本选项编辑器。
- 判断题显示“正确/错误”。
- 填空题支持一个或多个标准答案及可接受变体。
- 简答题和写作题显示参考答案、评分量规和解析，不显示选择项。
- 保存只创建新草稿版本；编辑前显示当前发布版本和草稿版本差异。
- 支持 `Ctrl/Cmd + S` 保存草稿。

### 4.6 Agent 生成协议

题库 Agent 不再默认产出 N 道孤立单选题。教师选择：

- 阅读题组
- 混合练习
- 写作任务
- 自动适配课程与课时

可信终结器协议升级为严格的：

```json
{
  "stimuli": [
    {
      "client_key": "passage-1",
      "title": "材料标题",
      "stimulus_type": "reading_passage",
      "content": {"paragraphs": ["..."]},
      "source_refs": []
    }
  ],
  "questions": [
    {
      "stimulus_key": "passage-1",
      "stimulus_order": 1,
      "question_type": "single_choice",
      "prompt": "..."
    }
  ]
}
```

完整协议仍要求答案、解析、难度、分值、知识点、学段和来源上下文。`stimulus_key` 只在本次 Agent 回复内使用，可信服务端在同一事务中转换为正式 ID。不存在的 key、题型不匹配、答案不合法或阅读题组少于两道题时整体拒绝并返回可修复错误，不写半套题组。

学科默认：

- 高中英语阅读题组：文本证据、推断、词义、结构/主旨和读写迁移中至少覆盖三类；不要求每套都包含所有类型。
- 小学语文阅读题组：按年级和课文类型覆盖信息提取、词句理解、内容概括、人物/主题和表达迁移；低年级不强行使用抽象术语。

## 5. BUG-402：题目编辑与试卷预览/编辑

### 5.1 试卷预览

每张试卷卡提供“预览”按钮，打开只读试卷窗口：

- 试卷标题、用途、时长、总分、版本和发布状态。
- 按 section 显示材料、题目、分值和作答区域。
- 同一材料只显示一次，其子题连续排列。
- 教师可切换“学生视图 / 含答案教师视图”。
- 学生视图不得包含参考答案、解析和教师量规。
- 预览读取冻结的 `paper_version_id`，不读取题库当前版本。

新增或扩展接口：

- `GET /papers/:paper_id?version_id=`：返回试卷元数据。
- `GET /papers/:paper_id/preview?version_id=&mode=student|teacher`：按权限补全冻结材料和题目。

### 5.2 试卷编辑

教师可以：

- 修改标题、用途和建议时长。
- 新增、删除、排序 section。
- 从已发布题库选择题目。
- 在 section 内拖动或按钮调整题目顺序。
- 查看当前草稿与已发布版本。
- 保存新版本后再次预览，确认后发布。

新增：

- `POST /papers/:paper_id/versions`
- `POST /papers/:paper_id/publish`

发布试卷也使用 `published_version_id`，不覆盖已开始的学生考试尝试。模拟考试创建时冻结试卷版本；已有 attempt 永远继续使用原版本。

## 6. BUG-403/404：思维导图编辑完成度

### 6.1 双击编辑

- 查看状态双击节点：进入编辑状态并打开节点内联名称输入框。
- 编辑状态双击节点：直接打开节点内联名称输入框。
- `Enter` 确认，`Esc` 取消；失焦只在内容合法且发生变化时提交到当前未保存文档。
- 双击空白画布不创建节点，避免误操作。
- 单击仍只负责选中节点。

### 6.2 节点颜色

节点新增可选字段：

```json
{
  "color_token": "teal"
}
```

允许令牌：`auto`、`teal`、`blue`、`indigo`、`violet`、`amber`、`orange`、`rose`、`slate`。

- 检查器提供色板圆点和“按层级自动配色”。
- 服务端校验令牌，不保存任意 CSS。
- 文本色由主题映射自动选择，必须达到可读对比度。
- 导出 PNG、SVG、HTML 必须保留颜色。

### 6.3 查看态白块

`.graph-body` 根据状态切换：

- 查看态：`grid-template-columns: minmax(0, 1fr)`。
- 编辑态：`grid-template-columns: minmax(0, 1fr) 250px`。

右侧检查器只能在编辑态占用布局宽度。窄屏时检查器改为内部抽屉，不压缩画布到不可用宽度。

### 6.4 同级排序

“上移/下移”改名为“同级前移/同级后移”，并在按钮旁说明只改变同一父节点下的顺序。

执行时同时：

1. 调整父节点 `children` 顺序。
2. 交换两个兄弟节点的纵向视图位置，或清除该兄弟组位置后执行一次受控布局。
3. 记录一次撤销快照。

按钮在首个/末个兄弟节点时禁用，不能允许“点击了但无变化”。

### 6.5 内容居中

“居中”不是恢复初始化 action。组件应：

1. 读取当前可见节点的图形边界。
2. 结合画布宽高计算 fit zoom，限制在安全范围。
3. 设置 ECharts graph 的中心和缩放，使全部可见节点留出统一边距。
4. 不修改节点业务坐标，不写入新版本，也不进入撤销栈。

验收要求是根节点和全部可见节点进入画布可视区，不只是缩放值回到 1。

## 7. BUG-405/406：作业批改到学生弱点的自动闭环

### 7.1 数据进入条件

弱点分析只使用以下正式证据：

- 已提交并规则判分完成的客观题。
- 教师已经发布成绩与反馈的作业提交。
- 已提交且客观题判分完成的模拟考试。

“学生完成提交”只能显示“等待教师批改”，不能在没有评分证据时猜测弱点。

### 7.2 自动投影

在以下事件后调用同一个确定性 projector：

- `FeedbackReleased`
- `MockExamSubmitted`
- 学生订正版本再次得到教师发布反馈

投影输入和优先级：

1. 客观题的 `knowledge_points + correct`。
2. 作业量规中低于阈值的维度，按 `rubric item id/label` 形成弱点证据。
3. 已由教师发布的最终反馈文本只用于解释，不直接让模型凭文本创造掌握度。

不再依赖 `strengths/issues` 与 `weaknesses/improvements` 这两套漂移字段来决定弱点。

### 7.3 指纹兜底

`GET /courses/:course_id/weakness-analysis` 计算当前正式证据指纹：

- 无快照：同步生成确定性快照。
- 指纹变化：生成新快照并返回。
- 指纹一致：返回已有快照。

Agent 分析属于可选的解释增强，不是学生看到基础弱点的前置条件。上游模型不可用时，确定性弱点、证据和补练入口仍然可用。

### 7.4 状态文案

- 已提交未批改：`作业已提交，等待教师发布成绩与反馈后形成弱点证据。`
- 已批改但没有错误聚集：`当前正式证据中没有明显弱点。`
- 没有提交：`完成作业或模拟考试后，这里会形成带来源的学习证据。`
- 投影失败：保留上次快照，并显示可重试的“证据暂未同步”，不能回退为“数据不足”。

## 11. 兼容与隔离边界

### 11.1 保持不变

- Education 数据库仍是题目、材料、试卷、成绩、画像和反馈的唯一业务真源。
- Sandbox 只用于 Agent 计算，不保存最终题组、试卷或画像。
- Agent 仍通过可信终结器和 Education Tool Gateway 写草稿，不直写数据库。
- 教师发布题目、试卷、成绩和反馈仍需要人工确认。
- 学生只能读取已发布题目/试卷和自己的提交、反馈、弱点、思维导图。
- 现有课程、课时、资产、作业版本和聊天双向关联保持兼容。

### 11.2 数据迁移

- 现有题目迁移时 `published_version_id = current_version_id`（仅对当前 `status=published` 的题目）。
- 现有试卷同理迁移发布指针。
- 现有题目 `stimulus_version_id = null`，归入“独立题”，不根据题干文本猜测题组。
- 现有思维导图节点缺少 `color_token` 时按 `auto` 渲染。
- 现有反馈字段只在读取时合并，不覆写历史行。

### 11.3 明确不做

- 不做完整 QTI 导入导出。
- 不做扫描答题卡识别。
- 不做 XMind 文件格式导入导出或多人实时协作。
- 不做任意 CSS 节点主题。
- 不在本阶段实现真实锚定批注。
- 不使用未校准的 BKT/IRT 掌握度概率。
- 不让 AI 建议分进入正式成绩。
- 不把所有题目强制变成阅读题组。

## 15. 自动化与完成门槛

### 15.1 后端

- 材料、题目和试卷的草稿/已发布指针迁移测试。
- 题组事务测试：无效子题不得留下孤立材料或半套题。
- 六种题型校验与答案规范测试。
- 题目编辑后旧试卷版本不可变测试。
- 试卷预览权限测试：学生响应不包含答案和量规。
- `FeedbackReleased` 后弱点投影测试。
- GET 指纹兜底和幂等测试。
- 按作业分布与课程作业趋势的统计口径测试。
- 教师/学生跨课程访问隔离测试。

### 15.2 前端

- 题组折叠、动态题型编辑和创建新版本测试。
- 试卷学生/教师预览切换与权限渲染测试。
- 思维导图双击、颜色、白块、同级排序、居中、撤销/重做测试。
- 批改页只存在一个教师反馈编辑器，AI 建议默认收起，不存在锚定批注入口。
- 成绩总览/画像模式切换、3 人分批和详情入口测试。
- 教学空间四按钮结构和通用弹窗内部滚动契约测试。

### 15.3 真实浏览器

- 使用真实教师和学生账号分别验收。
- 至少在 1440×900 和约 768px 宽度下检查布局。
- 检查控制台无新增 error。
- 弹窗必须实际滚动长内容，不能只检查 CSS 类存在。
- 思维导图必须实际双击、改色、排序、保存、刷新和导出。
- 成绩分布必须用两份不同作业切换验证数值变化。

### 15.4 完成定义

以下任一情况都不能报告 Phase 4 完成：

- 题库仍只能创建单选题。
- 阅读材料在每道子题中重复显示或重复存储。
- 编辑已发布题目后学生立即看到未重新发布的版本。
- 试卷预览只展示 ID 或 JSON。
- 思维导图颜色只存在前端内存，刷新丢失。
- 居中只是调用 restore 而没有把节点放入可视区。
- 教师已发布反馈但学生仍必须手动刷新快照。
- 成绩分布仍混合不同作业。
- 学生画像一次渲染全部成员。
- 页面滚动条与弹窗滚动条同时争抢。
- 只通过单元测试，没有真实教师/学生浏览器闭环。

## 16. 最终产品判断

本阶段完成后，Education 的题库才会从“题目 JSON 列表”变成符合语文和英语教学语义的材料题组与独立题库；思维导图才会具备用户可感知的编辑闭环；成绩、反馈、弱点和画像也会遵循同一条正式证据链。

Phase 4 的重点不是继续增加菜单，而是确保用户点击已有入口后得到正确对象、正确版本、正确统计口径和清晰反馈。
