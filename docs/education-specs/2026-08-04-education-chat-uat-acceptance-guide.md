# WeAgent Education 聊天与业务闭环验收指南

> 文档状态：可执行 UAT 基线  
> 验收环境：本机真实前后端、真实数据库、真实 Docker sandbox、真实模型 Provider  
> 验收对象：固定高中英语展示课程，不新建一套更容易通过的临时数据

## 1. 验收目标

本指南用于判断以下能力是否形成真实闭环，而不只判断页面是否能打开：

1. 新建“智慧教育”聊天后，课程、课时和教师/学生身份是否正确绑定。
2. Agent 是否实际调用受控 Education/RAG 工具，并生成数据库中的业务对象。
3. 教师能否完成课时编辑、PPT 生成与版本修改、资料检索、学生导入和作业分析。
4. 学生是否只能使用学生侧 Agent，并能查看自己的学习结果。
5. 聊天卡片、业务页面、预览和导出是否可以双向追溯。
6. 课程、角色、领域和灰度边界是否阻止越权与串数据。

## 3. 验收前置条件

开始前确认：

- Core API 监听 `5002`。
- Education API 监听 `5102`，健康检查返回 200。
- RAG API 监听 `5104`，健康检查返回 200。
- 前端监听 `8080`。
- MySQL、Redis 和 Docker 可用。
- `weagent-sandbox:latest` 为当前代码对应的镜像。
- 本机 Provider 配置可调用真实模型，不使用 mock 结果代替最终验收。

如果 Docker 未启动，可以浏览历史业务数据，但不能验收新的多 Agent 运行。

## 4. 能力入口与边界

### 4.1 全局新建 EDU 聊天可直接验收

在聊天页新建“智慧教育”会话，选择课程，课时可选。角色由课程成员关系自动确定，用户
不能选择教师或学生，也不需要选择微服务。

| 能力 | 新建聊天是否可用 | 说明 |
|---|---|---|
| 查看课程和课时 | 是 | 读取服务端绑定的课程上下文 |
| 新建或修改课时 | 是 | 教师可修改标题、分类、时长、顺序 |
| 根据教案和资料制作 PPT | 是 | 生成结构化课件、HTML 预览和可导出版本 |
| 修改 PPT 并保存新版本 | 是 | 追加不可变版本，不覆盖旧版本 |
| 检索课程知识库 | 是 | 资料研究员使用课程范围 RAG |
| 生成题目和组卷 | 是 | 写入题库/试卷库后显示可信业务卡片 |
| 刷新课程学情画像 | 是 | 只使用已有成绩、提交和教师反馈证据 |

### 4.2 必须从业务页带入上下文的 Agent 聊天

这些能力同样使用聊天和多 Agent，但不应从一个没有业务对象的空白聊天盲目执行：

| 能力 | 正确入口 | 原因 |
|---|---|---|
| 批量导入学生 | 教学空间 → Agent 导入名单 | 需要结构化名单、账号匹配和一次教师确认 |
| 分析单份学生提交 | 作业 → 某份提交 → AI 批改建议 | 需要绑定具体作业、提交和评分证据 |
| 学生作业弱点分析 | 学生教学空间 → 作业弱点 | 需要当前学生的已提交/已反馈证据 |
| 模拟考试 | 学生端 → 模拟考试 | 需要学生身份和课程题库范围 |
| 课程思维导图 | 学生端 → 课程思维导图 | 需要学生、课程和可选课时范围 |

业务页启动后会创建或找回对应 EDU 聊天；聊天仍显示 Agent 进度、结果卡片和“返回业务页”。

### 4.3 不应由 Agent 自动完成

- 不自动发布教师草稿、课件、题目或作业。
- 不自动删除课程业务对象。
- 不自动把 AI 建议写成正式成绩或正式教师反馈。
- 不允许学生调用教师 Agent 或教师写工具。
- 不允许 EDU 会话调用 RD 领域服务。
- 不把聊天文本、沙箱文件路径或模型声称的“成功”当作业务成功。

## 5. 教师端验收

### 5.1 登录、导航与角色

1. 使用固定教师账号登录。
2. 进入“智慧教育”，打开固定课程。
3. 检查导航包含教学空间、PPT 与课件、学生画像与评估、帮助中心。
4. 新建智慧教育聊天，选择固定课程和主要课时。

通过标准：

- 上下文显示“教师”。
- 没有角色切换器和微服务选择器。
- 教师 Agent 可见；学生 Agent 不混入教师任务。
- 刷新后会话仍在左侧历史列表中，课程/课时绑定不丢失。

### 5.2 课程上下文与课时修改

发送：

> 告诉我当前课程和课时的教学目标，并把当前课时时长改为 45 分钟。

通过标准：

- Agent 先读取真实课程上下文，不要求用户提供内部 ID。
- 聊天出现课时业务卡片。
- 返回教学空间刷新后，时长为 45 分钟。
- 回复不泄露 Token、RunGrant、内部 UUID 或工具原始协议。

### 5.3 PPT 生成、预览与导出

发送：

> 根据当前课时教案和课程资料，生成一份 8 页、paper_annotation 风格、可直接用于课堂的 PPT。重点呈现文本证据、情境反讽、CER 推理支架和一个退出任务。

通过标准：

- 聊天显示课程设计师、课件制作师和教学审校员的简化进度。
- 完成后出现课件业务卡片，而不是只回复文件路径或 JSON。
- 卡片显示标题、页数、主题、版本和版本时间。
- HTML 预览可打开，无 `Missing Authorization Header`。
- 逐页视觉预览与 HTML/PPTX 内容一致，共 8 页，无重复封面。
- PPTX 与 HTML 可以下载；PPTX 可正常打开且不是把图片简单拼成一页。
- “打开业务页面”回到对应课时的 PPT 与课件位置。

### 5.4 PPT 不可变版本

在原聊天继续发送：

> 把第 3 页改成“证据—推理—结论”结构，保留其他页面，并保存为新版本。

通过标准：

- 生成同一课件对象的新版本。
- 最新版本有新的版本号与时间。
- 旧版本仍可回看，未被覆盖。
- 业务页“协作历史”可以找回原聊天。

### 5.5 知识库与真实 RAG

1. 在课程知识中心上传一份正常 PDF，建议使用公开版权或已获授权的英文阅读材料。
2. 等待状态变为“可检索”。
3. 在 EDU 聊天发送：

> 只根据刚上传的课程资料，找出 Della 卖掉头发的三条文本证据，并说明每条证据如何服务于情境反讽教学。

通过标准：

- 上传、资产持久化和索引均成功。
- Agent 命中真实文档片段，显示来源摘要或知识资源卡片。
- `content` 摘要不被冒充为网页全文。
- 在另一门课程使用精确句子检索时返回无结果或无权访问。
- RAG 暂不可用时明确 fallback 到课程结构化资料，不伪造检索命中。

### 5.6 批量导入学生

1. 返回教学空间，点击“Agent 导入名单”。
2. 输入 1–3 个已存在平台账号的名单。
3. 检查解析结果后，在确认框中确认本次导入。

通过标准：

- 未确认时不得执行导入。
- 同名或无法唯一匹配的账号要求修正，不猜测用户。
- 成功后出现成员/课程业务卡片，成员列表显示姓名而不是 UUID。
- 重复运行不重复创建成员。
- 左侧聊天历史可找到本次“Agent 名单导入”会话。

### 5.7 题库与试卷库

发送：

> 根据当前课时材料生成一个阅读题组：保留一篇完整材料，包含事实定位、推断、简答和 100 字写作迁移题；总分 30 分。完成后再从这些题目中组成一份 25 分钟练习卷。

通过标准：

- 题目按课时进入题库，不把同一篇材料复制到每道题。
- 选择题选项规范显示为 `A. ... / B. ...`，无重复编号。
- 题型不局限于单选。
- 聊天出现题库和试卷业务卡片。
- 业务页可编辑题目、选择题目组卷并预览学生视图。
- 学生视图不泄露答案和解析。

### 5.8 学情与作业分析

课程级发送：

> 根据当前课程已经发布的作业、提交、得分和教师反馈刷新班级学情，列出三个最需要干预的证据点。

单份提交从“作业 → 学生提交”启动 AI 批改建议。

通过标准：

- 成绩总览可按作业切换，最高分、最低分、平均分、提交率和分布同步变化。
- 学生画像的判断可以回溯到具体作业证据。
- AI 批改建议默认可收起，只生成建议，不改变正式成绩。
- 教师确认并发布后，学生弱点页面才使用该正式反馈。

## 6. 学生端验收

### 6.1 角色和 Agent 隔离

1. 退出教师账号，使用固定学生账号登录。
2. 进入同一门固定课程。
3. 新建智慧教育聊天并选择该课程。

通过标准：

- 角色自动为“学生”。
- 只显示学习规划师、练习教练、笔记整理师。
- 不显示课程设计师、课件制作师、习题生成器、学情分析师等教师 Agent。
- 学生尝试“修改课时”或“生成教师课件”时得到明确拒绝，不执行工具。

### 6.2 作业、弱点与课程资料

1. 打开教学空间，检查课件与材料、完成作业、作业弱点。
2. 打开一份已发布作业并查看提交/反馈状态。
3. 从作业弱点启动或找回 Agent 分析。

通过标准：

- 只看到已发布且对学生可见的材料。
- 长作业内容在合理高度内滚动，不拉长整张卡片。
- 弱点来自该学生的得分、提交和正式教师反馈，不读取其他学生数据。
- 未完成或未反馈的作业显示“证据不足”，不凭空生成弱点。

### 6.3 模拟考试与思维导图

通过学生端独立入口分别生成一个模拟考试和一张课程/课时思维导图。

通过标准：

- 模拟考试只使用当前课程可用题库，不泄露答案。
- 思维导图可以双击编辑节点、修改受控颜色、撤销/重做、居中和导出。
- 查看状态没有遮挡画布的空白编辑面板。
- 结果进入学生自己的业务数据，并在聊天显示对应卡片。

## 7. 聊天卡片与双向追溯

对课件、课时、题库、试卷、知识资源、学生画像、作业分析和思维导图至少各抽查一个结果：

1. 卡片标题、状态、摘要、版本时间与业务数据库对象一致。
2. “预览”打开经过认证的真实内容，不出现 401、403 或 `Missing Authorization Header`。
3. “打开业务页面”进入对应对象，而不是 Education 首页。
4. 从业务页“返回聊天/协作历史”找回同一会话。
5. 刷新浏览器、重启 Core、删除旧 sandbox 后，历史卡片和双向跳转仍可恢复。
6. 旧版本产物从聊天历史查找；业务页默认只突出最新一次产物。

## 8. 权限、灰度与兼容性

### 8.1 必测拒绝场景

- 学生伪造教师 Agent：预检拒绝。
- 学生调用教师写工具：403。
- EDU Agent 调用 RD 服务：拒绝。
- 课件 Agent 借用未授权 RAG 服务：拒绝。
- 跨课程检索教师私有 PDF：无结果或拒绝。
- 使用通用微服务 API 调用 EDU 写接口：拒绝，并引导使用受控 `education_action`。

### 8.2 灰度

- 关闭 `feature.education.chat.manual_create`：不能新建 EDU 聊天，已有历史仍可读。
- 关闭 `ui.chat.card.education`：卡片隐藏或降级，但业务对象不丢失。
- 关闭 `feature.education.rag.enabled`：RAG 不执行，课程结构化资料 fallback 可用。
- RD 历史会话、RD 卡片和 Office 会话不受 EDU 灰度影响。

## 10. 最终通过标准

以下全部满足才算“Education 聊天与业务闭环通过”：

- 教师和学生可以使用固定账号登录，课程角色自动正确识别。
- 新建 EDU 聊天能用自然语言完成至少一次课时修改和一次 8 页 PPT 生成。
- PPT 有真实 HTML 预览、PPTX/HTML 导出、逐页视觉结果和不可变版本。
- 真实 PDF 完成上传、索引、检索和跨课程隔离。
- 名单导入和单份作业分析从业务页带上下文进入聊天，并遵守确认边界。
- 至少一种题库/试卷、学情、思维导图结果形成可回溯业务卡片。
- 聊天与业务页面双向跳转、刷新和重启恢复正常。
- 学生无法看到教师 Agent、教师草稿、答案或其他学生数据。
- 不存在“模型只回复成功但业务对象未写入”的假成功。
- EDU 灰度不会影响 RD/Office 既有能力。
