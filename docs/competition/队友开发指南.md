# WeAgent 领域隔离多Agent平台 — 队友开发指南

## 1. 架构概览

```
┌─────────────────────────────────────────────┐
│ 前端 (Vue.js + ElementUI, 单端口 8080)        │
│   WorkspaceSwitcher → 切换领域/工作空间        │
│   Sidebar → 按 grayscale 配置动态显隐菜单       │
│   /admin/grayscale → 灰度配置控制台             │
└────────────┬────────────────────────────────┘
             │  /api/*
┌────────────▼────────────────────────────────┐
│ 核心服务 (:5002, 数据库 weagent_shared)       │
│   认证/会话/消息/Agent调度/沙箱/工作空间/灰度    │
│   /api/domain/{domain}/* → 代理到领域服务      │
└──┬─────────┬─────────┬──────────┬───────────┘
   │         │         │          │
   ▼         ▼         ▼          ▼
智能研发     智慧教育    智慧办公    RAG检索
 :5101       :5102      :5103     :5104
weagent_rd  weagent_edu weagent_office weagent_rag
```

**核心原则：**
- 领域服务只负责本领域的数据处理和存储，不包含 Agent 调度
- Agent 相关 API 统一由核心服务处理
- 前端通过 `/api/domain/{domain}/*` 访问领域服务
- 所有服务共用同一 JWT SECRET_KEY

## 2. 环境准备

### 2.1 数据库

创建 5 个数据库（执行一次）：

```sql
CREATE DATABASE IF NOT EXISTS weagent_shared CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS weagent_rd CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS weagent_edu CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS weagent_office CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS weagent_rag CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

初始化核心服务数据库：

```bash
cd backend
mysql -u root -p weagent_shared < sql/migration_v2.sql
```

### 2.2 Python 环境

```bash
cd backend

# 创建虚拟环境
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt

# 安装 weagent_core 包（开发模式）
pip install -e .
```

### 2.2.1 Ollama（RAG 服务依赖）

RAG 服务默认使用 Ollama 本地 Embedding 模型：

```bash
# 安装 Ollama: https://ollama.com/download
# 拉取 Embedding 模型
ollama pull nomic-embed-text:latest
```

如果使用 OpenAI Embedding（备选），在 `services/rag/.env` 中设置：
```
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_API_KEY=sk-xxx
```

### 2.3 配置 JWT 密钥

所有服务的 `JWT_SECRET_KEY` 必须一致。复制核心服务的密钥：

```bash
# 核心服务 .env 中的 JWT_SECRET_KEY
JWT_SECRET_KEY=<从核心服务 .env 复制>
```

### 3.2 领域服务（队友各自维护）

**rd / edu / office 三个领域服务**结构简洁，只需两个文件：

```
services/{domain}/
├── .env         # 从 .env.example 复制并修改
├── config.py    # 配置
└── app.py       # 入口 + 蓝图注册
```

启动方式：

```bash
cd backend/services/rd    # 或 edu / office
cp .env.example .env      # 编辑数据库密码和 JWT 密钥
python app.py
```

**RAG 检索服务 (:5104)** 结构更复杂，是已完整实现的微服务：

```
services/rag/
├── .env                        # 环境变量（含 EMBEDDING_PROVIDER 等）
├── config.py                   # 配置（含 RAG 专用配置项）
├── app.py                      # 手动创建 Flask app（非 DomainServiceBase）
├── models/
│   ├── database.py             # db = SQLAlchemy(app)
│   ├── document.py             # 文档 ORM 模型
│   └── chunk.py                # 分块 ORM 模型
├── controllers/
│   ├── document_controller.py  # 文档上传/下载/爬取/确认/删除/列表 API
│   ├── search_controller.py    # 语义搜索 API
│   └── status_controller.py    # 服务健康状态 API
├── services/
│   ├── chunker.py              # 文本分块逻辑
│   ├── embedding_service.py    # Embedding 调用（Ollama / OpenAI）
│   ├── vector_service.py       # 向量存储操作
│   └── simple_vector_store.py  # 基于 SQLite 的向量存储（替代 ChromaDB）
└── utils/
    ├── parser.py               # 多格式文档解析（PDF/TXT/MD/DOCX/CSV）
    └── scraper.py              # 网页爬取（requests + BeautifulSoup）
```

**RAG 服务启动**（必须从 `backend/` 目录启动，因为 `config.py` 使用相对路径定位 `.env`）：

```bash
cd backend
python services/rag/app.py
# → http://127.0.0.1:5104
```

**RAG 服务技术要点**：
- **Embedding 模型**：默认使用 Ollama `nomic-embed-text:latest`，768 维向量；也可配置为 OpenAI `text-embedding-3-small`（1536 维）
- **向量存储**：使用自研 `SimpleVectorStore`（SQLite 后端 + cosine 相似度搜索），替代 ChromaDB。原因：ChromaDB 依赖 onnxruntime，在 Windows Python 3.12 上存在 segfault 兼容性问题
- **文档处理**：上传后先预览，用户确认后通过**后台线程异步**执行"分块 → 向量化 → 入库"，避免长文本处理导致 HTTP 超时
- **SQLAlchemy JSON 列**：对 `extra_meta` 等 JSON 列做 in-place 修改后，必须调用 `flag_modified(doc, 'extra_meta')` 才能持久化

## 4. 开发规范

### 4.1 领域服务后端开发

#### Model（数据模型）

在领域服务的 `models/` 目录创建模型，使用 `app.db`（DomainServiceBase 提供的 SQLAlchemy 实例）：

```python
# services/edu/models/course.py
from app import db

class Course(db.Model):
    __tablename__ = 'edu_courses'

    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(200), nullable=False)
    user_id = db.Column(db.String(36), nullable=False)

    def to_dict(self):
        return {
            'id': self.id,
            'name': self.name,
            'user_id': self.user_id,
        }
```

#### Service（业务逻辑）

使用类 + 单例模式，返回 `(result, error)` 元组：

```python
# services/edu/services/course_service.py
from app import db
from models.course import Course

class CourseService:
    def get_courses(self, user_id):
        courses = Course.query.filter_by(user_id=user_id).all()
        return [c.to_dict() for c in courses], None

    def create_course(self, user_id, data):
        course = Course(name=data['name'], user_id=user_id)
        db.session.add(course)
        db.session.commit()
        return course.to_dict(), None

course_service = CourseService()
```

#### Controller（API 路由）

使用 Blueprint，`@jwt_required()` 鉴权：

```python
# services/edu/controllers/course_controller.py
from flask import Blueprint, request
from flask_jwt_extended import jwt_required, get_jwt_identity
from services.course_service import course_service

course_bp = Blueprint('course', __name__)

@course_bp.route('/api/edu/courses', methods=['GET'])
@jwt_required()
def list_courses():
    user_id = get_jwt_identity()
    result, error = course_service.get_courses(user_id)
    if error:
        return {'code': 400, 'message': error}, 400
    return {'code': 200, 'data': result}

# 在 app.py 中注册：
# from controllers.course_controller import course_bp
# app.register_blueprint(course_bp)
```

### 4.2 前端开发

#### API 模块

遵循现有模式：

```js
// src/api/myFeature.js
import axios from './axios'

export function getData(params) {
  return axios.get('/domain/edu/courses', { params })
}
```

#### Store 模块

```js
// src/store/modules/myFeature.js
import { getData } from '../../api/myFeature'

export default {
  namespaced: true,
  state: { items: [], loading: false },
  mutations: { SET_ITEMS(state, items) { state.items = items } },
  actions: {
    async fetchData({ commit }) {
      const res = await getData()
      if (res.code === 200) commit('SET_ITEMS', res.data)
    },
  },
}
```

注册到 `store/index.js`：
```js
import myFeature from './modules/myFeature'
// 添加到 modules: { ..., myFeature }
```

#### 页面组件

每个页面使用 `DomainPlaceholder.vue` 作为初始模板，替换为核心业务组件。

### 4.3 灰度配置

灰度配置通过 `grayscale_config` 表管理，控制 UI 元素的可见性和功能的启用/禁用。

**前端使用：**
```js
// 检查某个功能是否可见
this.$store.getters['grayscale/isVisible']('edu', 'ui.sidebar.courses')

// 获取当前领域的可见配置
this.$store.getters['grayscale/visibleConfigs']('edu')
```

**新增灰度项：**
- 在 `grayscale_config` 表插入新记录
- Sidebar 菜单项在 `DOMAIN_NAV` 对象中注册（`components/Sidebar/index.vue`）
- 前端通过 `config_key` 匹配显隐

## 5. API 约定

### 请求格式
- Content-Type: `application/json`
- Authorization: `Bearer <JWT_TOKEN>`

### 响应格式
```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

### HTTP 状态码
| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 参数错误 |
| 401 | 未登录/token过期 |
| 404 | 资源不存在 |
| 500 | 服务器错误 |
| 502 | 领域服务不可达（网关代理） |

### 领域 API 路径
领域服务注册的路径必须是 `/api/{domain}/xxx` 格式，因为核心服务的网关会将 `/api/domain/{domain}/xxx` 转发到 `http://127.0.0.1:{port}/api/{domain}/xxx`。
