# 外部服务接入指南

## 平台怎么工作的

用户创建会话时勾选要用的服务（rd / edu / office / rag），平台把选中的服务信息注入 Agent 沙箱容器。Agent 通过 `host.docker.internal` 直接 HTTP 调你们的 API，拿到数据后通过 `weagent-report` 上报结构化卡片到前端展示。

```
用户选服务 → 创建会话 → Agent 拿到服务列表 + spec → curl 调你的 API → 卡片上屏
```

以 RD 为例：用户说"列出我的需求"，Agent 查 spec 知道有 `/api/rd/projects/{id}/requirements`，调完逐条发 `weagent-report '{"type":"requirement_card",...}'`，前端渲染成需求卡片。

## 一、数据库兼容（主服务 weagent 库）

平台为支持多领域在主服务数据库做了以下改动，你和同事如果本地有 weagent 库需要同步。**如果你也要改主服务表结构，同样追加到 migration_v2.sql。**

### 1.1 新增表

| 表 | 说明 |
|----|------|
| `workspaces` | 工作空间，按 domain 隔离（rd/edu/office），含 `sub_role` 字段（edu 区分 teacher/student） |
| `grayscale_config` | 灰度配置，控制 UI 可见性，含 `domains` JSON 字段（common 域跨领域生效用） |

### 1.2 已有表新增字段

| 表 | 字段 | 类型 | 说明 |
|----|------|------|------|
| `users` | `role` | VARCHAR(20) 默认 `'user'` | admin / user |
| `conversations` | `workspace_id` | VARCHAR(36) FK | 关联工作空间 |
| `conversations` | `services` | JSON | 启用的服务列表，如 `["rd","rag"]` |
| `conversations` | `project_id` | VARCHAR(36) | 关联项目 ID |
| `conversations` | `kb_domain` | VARCHAR(20) | 知识库领域范围 |
| `conversations` | `kb_document_ids` | JSON | 知识库文档筛选 |

### 1.3 迁移方式

完整 DDL + 种子数据在 `backend/sql/migration_v2.sql`，新库直接跑。老库用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 兼容，不会覆盖已有数据。

## 二、沙箱镜像兼容

镜像文件 `backend/app/sandbox/Dockerfile`，基于 `python:3.11-slim`，装了 Node 20 + Claude CLI + flask/requests。

### 2.1 新增的定制内容

| 组件 | 说明 |
|------|------|
| `bin/weagent-report` | 卡片上报验证脚本，Agent 发卡片必经此脚本校验 |
| `bin/weagent-service` | 后台服务管理脚本 |
| `container/agent.py` | Agent 系统提示，含卡片类型注册和格式示例 |
| `container/orchestrator.py` | 多 Agent 编排，含卡片服务端二次验证 |

### 2.2 注意

- 镜像以非 root 用户 `agent` 运行，Claude Code 需要 `--dangerously-skip-permissions`
- `bin/` 和 `container/` 是 `COPY` 进镜像的，不是 volume 挂载。**改任何文件都要重建：**

```bash
cd backend/app/sandbox && docker build -t weagent-sandbox:latest .
```

## 三、你的服务需要提供两个端点

### `/api/{domain}/spec` — 服务自描述

Agent 靠这个发现你能干什么：

```json
{
  "service": "edu",
  "version": "1.0.0",
  "description": "智慧教育领域服务",
  "base_url": "http://localhost:5102",
  "status": "healthy",
  "capabilities": [
    { "name": "课程管理", "description": "课程的CRUD与状态管理" }
  ],
  "popular_endpoints": [
    { "method": "GET", "path": "/api/edu/courses", "description": "获取课程列表" }
  ]
}
```

`popular_endpoints` 的接口会以 curl 示例注入 Agent 系统提示，放 5~10 个常用接口。

### `/api/{domain}/health` — 健康检查

```json
{ "status": "healthy", "version": "1.0.0", "dependencies": { "database": "connected" } }
```

用与主服务相同的 `JWT_SECRET_KEY` 验证请求。

## 五、灰度配置（控制 UI 可见性和领域隔离）

灰度数据存 `grayscale_config` 表。前端检查逻辑：

1. 先查当前 domain 有没有这条 key
2. 没有则查 `domain='common'` 的同名 key，看它的 `domains` JSON 是否包含当前 domain
3. 都没找到则默认可见

| `ui.chat.tabs.agent_config` | 聊天标签-Agent配置 | rd, edu, office |
| `ui.chat.tabs.artifacts` | 聊天标签-产物 | rd, edu, office |
| `ui.chat.tabs.logs` | 聊天标签-日志 | rd, edu, office |

| `ui.chat.tabs.knowledge_base` | 聊天标签-知识库 | rd, edu, office |

### 5.2 各领域专属灰度

这些只在自己 domain 下：

**edu：** `ui.sidebar.courses` / `assignments` / `resources` / `grades` / `students`

**office：** `ui.sidebar.documents` / `meetings` / `approvals` / `reports` / `schedules`

**rd：** `ui.sidebar.projects` / `repos` / `reviews` / `builds`

### 5.3 加新的灰度 key

改 `backend/app/__init__.py` 三处：

**① `wired_keys`（约第 214 行）** — 白名单，不在此列表的 key 启动时会被清理：

```python
# 领域独有功能（侧边栏等）→ domain='edu' 或 'office'
'ui.sidebar.xxx',

# 跨领域共享（卡片、标签等）→ domain='common'，通过 domains JSON 控制生效范围
'ui.chat.card.xxx',
```

**② `_seed_grayscale_configs()`（约第 334 行）** — 库为空时写入：

```python
# 领域独有
('ui.sidebar.xxx', '侧边栏-XXX', 'ui', 'edu', 1, 1),
# common 域（限制生效领域）
('ui.chat.card.xxx', '聊天-XXX卡片', 'ui', 'common', 1, 1, ['edu', 'office']),
```

**③ `_migrate_grayscale_configs()`（约第 202 行）** — 每次启动执行，用 `INSERT IGNORE` 给已有数据库补数据：

```python
for key, name, domains in [('ui.chat.card.xxx', '聊天-XXX卡片', ['edu', 'office'])]:
    conn.execute(_text(
        "INSERT IGNORE INTO grayscale_config "
        "(config_key, config_name, config_type, domain, enabled, visible, domains) "
        "VALUES (:key, :name, 'ui', 'common', 1, 1, :domains)"
    ), {'key': key, 'name': name, 'domains': json.dumps(domains)})
```
